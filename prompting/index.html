Prompting, from clear prompts to attacks and defenses

How to write a prompt that works, the main techniques and when to use each, how attackers use prompts, and why good design matters more than any prompt. Every lesson has a step-by-step animation, examples, a lab and a practice desk.

Why a prompting track

Every attack and defense on this site goes through a prompt. To attack an LLM app you need to know how prompts are built. To defend one you need to know where prompts break. This track starts with how to write a clear prompt and ends with why prompts alone cannot secure an app.

  • Lessons 1 and 2. How to prompt, and the main ways of prompting, from zero-shot to ReAct.
  • Lesson 3. System prompts, roles and the instruction hierarchy.
  • Lesson 4. Prompting for security work, with evidence and checkable output.
  • Lesson 5. Adversarial prompting. Jailbreak families, automated attacks and honest measurement.
  • Lesson 6. Defensive prompting, its limits, and the design patterns that work when the model is fooled.
Key point

Every lesson ends with a practice desk. Some questions ask you to name the technique, pick the right prompt, write a prompt, or find the flaw in one.

The track follows the first half of the Red Teaming and Securing Generative AI course at NYU Tandon. See the red teaming course map for the week-by-week match.
