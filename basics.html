Step 01

AI and machine learning

A normal program follows rules that a person writes. For example, "if the email contains this exact link, mark it as spam". The rule works only for the cases the person thought of.

A machine learning (ML) model writes its own rules. You give it many examples with the right answers. It finds the patterns that connect the examples to the answers. Then it uses those patterns on new data that it has not seen.

Model
The learned rules, stored as a large set of numbers called weights or parameters.
Training
The process that adjusts the weights until the model gives good answers on the examples.
Label
The right answer attached to an example, such as "spam" or "not spam".
Inference
Using a trained model on new data. Most attacks in this course happen here.
Why security people care

Security tools use ML for spam filters, malware detection and alert triage. Attackers can also attack the model itself. They can change its training data (poisoning) or craft inputs that it gets wrong (evasion).

Quick check

A spam filter learns from one million emails that people marked as spam or not spam. What kind of learning is this?

Each email comes with the right answer, so the model learns from labeled examples. That is supervised learning. Unsupervised learning has no labels and looks for groups or outliers.

Step 02

How a large language model writes

A large language model (LLM) is a model trained on a very large amount of text. It does one job. It reads text and predicts the next small piece of text. Then it adds that piece and predicts again.

  1. The text is cut into tokens. A token is often a short word or a part of a word.
  2. Each token becomes a list of numbers called an embedding. Tokens with similar meaning get similar numbers.
  3. The transformer layers mix the embeddings so that each token carries information from the tokens around it.
  4. The model gives a probability to every possible next token.
  5. The app picks one token. A setting called temperature controls how random that pick is.
  6. The new token goes onto the end of the text, and the loop starts again.
Why security people care

The model picks likely text, not true text. When it does not know, it can still write a fluent, confident answer. This is called a hallucination. Tokens also matter for attacks. A filter that checks words can miss a word that is split into odd tokens, encoded, or written in another language.

Quick check

What does an LLM actually predict at each step?

An LLM has no fact database. It scores every possible next token, the app picks one, and the loop repeats. That is why the same question can give different answers.

Step 03

Prompts, roles and the system prompt

A prompt is all the text the model reads before it writes. Chat apps build the prompt from messages with roles.

  • The system message holds the developer's instructions, such as "You are a support bot for an airline. Do not give refunds."
  • The user message holds what the person types.
  • The assistant messages hold what the model wrote before.

Before the model runs, the app joins all messages into one long text with special marker tokens between them. The model was trained to give the system message more weight. But it is still all one stream of tokens.

Key point

A system prompt is not a security control and it is not a safe place for secrets. A user can often make the model repeat it or ignore it. Put real rules, such as "no refunds", in code outside the model.

Quick check

A developer puts an API key in the system prompt and writes "never reveal this key". Is the key safe?

The instruction only makes a leak less likely. Prompt leaking attacks such as PLeak recover system prompts from real apps. Keep keys in the server code, where the model never reads them.

Step 04

RAG, giving the model your documents

A model only knows its training data, and that data stops at a date. Retrieval-augmented generation (RAG) adds fresh or private knowledge. It does not change the model. It pastes the right documents into the prompt.

  1. Before use, the app cuts documents into chunks. An embedding model turns each chunk into a vector. The vectors go into a vector database.
  2. When a user asks a question, the app turns the question into a vector too.
  3. The database finds the chunks whose vectors are closest to the question vector. Close vectors mean similar meaning.
  4. The app pastes those chunks into the prompt and asks the model to answer from them.
Why security people care

Every chunk that the database returns goes straight into the prompt. If an attacker can add a document, they can add instructions (indirect prompt injection) or false facts (poisoning). If the search ignores who is asking, a user can get chunks from documents they must not see.

Quick check

Where should a RAG app check that a user is allowed to read a document?

Once a confidential chunk is in the prompt, the model may use it. ConfusedPilot shows this in a real product. Filter by permission in the search, outside the model.

Step 05

Agents and tools

An agent is an LLM that runs in a loop and can use tools. A tool is a function that the app makes available, such as "search the web", "read an email" or "run SQL".

  1. The model reads the task and decides which tool to use.
  2. The model writes a tool request as text, for example the tool name and its arguments in JSON.
  3. The app runs the tool. The model does not run anything itself.
  4. The app adds the tool result to the context. The model reads it and decides the next step.
  5. The loop stops when the model says the task is done or a limit is reached.
Why security people care

An agent turns text into actions. If an attacker steers the text, they steer the actions. Give each agent only the tools and permissions that its task needs. Ask a person to approve actions that cost money, delete data or send messages. Treat every tool result as untrusted input, the same as user input.

Quick check

An email agent has full read and send access to a mailbox. Its only job is to file travel receipts. Which OWASP risk is this?

The agent has more permission than its task needs. If an injected email fools it, it can read or send anything. That is LLM06, excessive agency.

Step 06

MCP, a plug for tools

The Model Context Protocol (MCP) is an open standard that Anthropic published in November 2024. It gives AI apps one common way to connect to tools and data.

  • The host is the AI app, such as a chat app or a code editor.
  • The host runs one client for each server it connects to.
  • An MCP server offers tools, data (resources) and prompt templates. Anyone can write one.

Each tool has a name and a text description. The model reads the descriptions to decide which tool to use.

Tool poisoning
A tool description contains hidden instructions for the model.
Rug pull
A server changes a tool's behavior or description after you approved it.
Tool shadowing
One server's description changes how the model uses another server's tool.
Token theft
A server or an injected prompt steals the access tokens that the host stores for other services.
How to defend

Install servers only from sources you trust. Read the tool descriptions. Pin server versions so that a change needs a new approval. Give each server the smallest permission it needs. Show the user each tool call before it runs. Damn Vulnerable MCP Server lets you try all four attacks above.

Step 07

Why LLM apps are hard to secure

Old injection bugs, such as SQL injection, happen when data is read as code. The fix is to keep the two apart. A parameterized query sends the SQL command and the user data on separate channels. The database never runs the data.

An LLM has no separate channel. Instructions and data arrive as one stream of tokens. The model decides from the words alone which text to obey. Any text that reaches the prompt can act as an instruction. That includes web pages, emails, documents, tool results and memory.

This is the root cause of prompt injection, the number one risk in the OWASP LLM Top 10. There is no complete fix today. So defenders assume that the model can be fooled and limit what a fooled model can do.

Quick check

Which defense still works when the model is fully fooled?

Prompts and delimiters ask the model to behave. A fooled model can ignore them. Least privilege and checks in code do not depend on the model, so they limit the damage even after the injection works.

Step 08

Practice safely, then start week 1

You now know the parts of an LLM app and why they break. The next step is practice. Follow these rules from the first day.

  1. Attack only systems that you own or that give you permission. The labs and CTFs in the plan are built for this.
  2. Use a local model on Ollama as your first target. It is free and it is yours.
  3. Run payload files, such as the pickle lab in week 5, in a throwaway virtual machine or container.
  4. If you find a leaked key or personal data, do not use it. Report it to the owner.
  5. Keep a notes file. Write what you tried, what worked and why. It becomes your portfolio.
