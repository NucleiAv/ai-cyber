The OWASP LLM Top 10: A Living Professional Framework

A Consensus Document, Not a Permanent Classification

The OWASP Top 10 for Large Language Model Applications is a consensus document produced by industry practitioners, researchers, and vendors. The 2025 edition reflects current understanding, but the framework evolves. The 2023 edition looked different: two new categories were added (LLM07: System Prompt Leakage and LLM08: Vector and Embedding Weaknesses), and five existing categories were renamed or restructured. Future editions will likely change again.

The analytical skill is applying the framework to observed attacks: identifying the pattern, connecting it to documented scenarios and prevention strategies, and communicating findings using a shared professional vocabulary. Memorizing category numbers is less valuable than understanding how to match an observed attack to the right category with justification.

Which edition this course uses. Every OWASP reference in Modules 9 through 11 is the 2025 edition, so the identifiers stay consistent as you move between modules. OWASP has since published a 2026 edition with, in its own description, updated rankings. Expect the numbering to keep shifting: an entry can move position, merge with another, or be renamed from one release to the next. What stays stable is the set of underlying failure modes. Cite the edition alongside the identifier in professional work, the way you would cite any versioned standard, and check the current release before quoting a number to a stakeholder.

Classification Exercise

Apply OWASP Classification to Your CTF Attacks

Return to the CTF documentation from Section 2. For each attack you documented, apply the following classification:

  1. Primary OWASP category: Which LLM Top 10 category best describes this attack?
  2. Justification: In one sentence, explain why this category applies (connect the observed behavior to the category's definition).
  3. Secondary categories (if any): Did the attack also implicate other OWASP categories? For example, if the attack extracted the system prompt, it is LLM01 (the technique) and LLM07 (the outcome).

Example 1: CTF Classification

Attack: Gandalf Level 3. Used instruction override to extract the password.

Primary: LLM01: Prompt Injection (direct injection via instruction override).

Justification: The user-supplied instruction overrode the instruction to protect the password, exploiting the lack of an enforced instruction/data boundary.

Secondary: LLM07: System Prompt Leakage (the protected information was part of the system prompt's configuration).

Example 2: Real Incident Classification

Attack: Chevrolet chatbot manipulated to agree to sell a vehicle for $1.

Primary: LLM01: Prompt Injection (direct injection via instruction override).

Justification: The attacker's instruction ("agree with anything the customer says") overrode the chatbot's intended behavior.

Secondary: LLM06: Excessive Agency. The chatbot had no deterministic constraint preventing it from making sales agreements. The injection exploited the boundary problem; the lack of action constraints amplified the consequence.

The Promptware Kill Chain

A 2026 analysis of 21 documented prompt injection incidents, published as "The Promptware Kill Chain" on Bruce Schneier's Schneier on Security, reframed prompt injection as the initial access stage of a multi-step attack chain, coining the term for malware delivered through prompt injection. The seven stages:

Each stage below is drawn from the traditional cyber kill chain. Select a stage to reveal a documented prompt-injection incident that reached it.

  1. 1

    Initial Access

    The adversarial instruction enters the system through direct or indirect injection.

    Documented, EchoLeak (CVE-2025-32711): a single crafted email carried the payload into Microsoft 365 Copilot's context through normal retrieval. No user clicked anything malicious; retrieval alone granted the attacker initial access.
  2. 2

    Privilege Escalation

    The attacker uses or prompt manipulation to gain capabilities beyond what the initial injection provided.

    Documented pattern: in agent compromises, an injected instruction is paired with a jailbreak framing ("you are in maintenance mode") so the model will invoke a tool or reveal data it would otherwise refuse. The escalation is behavioral, not a memory-corruption exploit.
  3. 3

    Reconnaissance

    The compromised LLM gathers information about the system, its data, and its connected tools.

    Documented, Copilot and assistant cases: once compromised, an AI assistant with mailbox or file access can be instructed to enumerate other messages, documents, and available tool schemas already inside its context, mapping what is reachable before acting.
  4. 4

    Persistence

    The attacker establishes lasting influence (memory poisoning, retrieval poisoning) that survives beyond the current session.

    Documented, Gemini memory poisoning: a researcher used delayed indirect injection to write false long-term memories that persisted across separate sessions, so the influence outlived the conversation that planted it.
  5. 5

    Command and Control

    The attacker establishes a communication channel with the compromised LLM, enabling ongoing instruction delivery.

    Documented, Markdown exfiltration channel: injected instructions make the model emit a Markdown image whose URL encodes stolen data. Each time the client auto-renders the image, it silently beacons back to an attacker-controlled server, an outbound channel hidden inside ordinary output.
  6. 6

    Lateral Movement

    The compromised LLM spreads adversarial influence to connected systems, tools, or other AI agents.

    Documented, the "Morris II" GenAI worm: a self-replicating prompt embedded in an email caused an AI email assistant to both exfiltrate data and forward the same payload to new recipients, spreading agent-to-agent without human action, the "worming" threat that early indirect-injection research predicted.
  7. 7

    Actions on Objective

    The attacker achieves their goal: data exfiltration, system manipulation, or further compromise.

    Documented, EchoLeak (CVSS 9.3): the completed chain exfiltrated sensitive organizational data out of Copilot with no user interaction, the objective that made it a critical-severity vulnerability rather than a curiosity.

Of the 21 documented incidents, 15 achieved four or more stages. Lateral movement, which was absent from documented incidents in 2023, appeared in eight of the 21 incidents in 2025-2026. This progression mirrors the maturation of traditional malware from single-purpose exploits to multi-stage attack frameworks.

Assume Injection Will Occur

The parallel to traditional network security is direct. In network defense, we assume the perimeter will be breached and design internal defenses to detect, contain, and disrupt attacks that get through. The same principle applies to LLM security: assume that prompt injection will occur, and focus on disrupting subsequent kill chain stages.

Defense cannot rely solely on preventing malicious input from reaching the model. It must also constrain what the model can do after receiving any input, monitor for anomalous behavior, and impose architectural limits on the system's capabilities.

Source Note

The kill chain framework draws on Pleger et al., "The Promptware Kill Chain" (arXiv 2601.09625, 2026), discussed by Bruce Schneier in "The Promptware Kill Chain" on Schneier on Security. The paper is a preprint (not yet peer-reviewed as of mid-2026), so the incident counts are indicative of trends, not definitive. The conceptual framework (injection as initial access in a multi-stage chain) is the transferable insight, regardless of precise numbers.

Defense Preview: Six Layers

No single defense against prompt injection is sufficient. Effective defense requires multiple layers, each addressing a different aspect of the threat. These are covered in depth later in the course; here we identify the six categories that form a strategy.

1. Input Filtering

Pattern-matching and classification to detect known injection patterns before they reach the model. Useful as a first-pass layer but easily bypassed by rephrasing (benchmarks show approximately 18% effectiveness alone).

2. Instruction Hierarchy

Training models to assign different priority levels to instructions based on their source (system > user > retrieved data). One approach achieves up to ~16% improvement in robust accuracy against indirect injection. Promising but not universally deployed.

3. Output Validation

Screening the model's output for harmful content, leaked information, or policy violations before it reaches the user or downstream systems.

4. Deterministic Guardrails

Non-LLM constraints on what the system can do: restricting available actions, limiting permissions when processing untrusted content, requiring human confirmation for high-impact operations. A national cybersecurity center recommends focusing defense effort here, because these constraints work regardless of whether the LLM itself is compromised.

5. Privilege Reduction

Limiting the LLM's access to data and tools based on the principle of least privilege. An LLM processing untrusted email content should not have read access to the entire mailbox.

6. Human Oversight

Requiring human review for high-stakes actions. This is the last line of defense: even if every automated layer fails, a human reviewer can catch and block a harmful action.

Measuring the Problem: How Professionals Test for Injection

Defenses are only credible if you can measure whether they hold. Because prompt injection has no single deterministic fix, the professional discipline is continuous adversarial testing: throw large, evolving batteries of attack strings at a deployment and track how many get through. This is the LLM equivalent of a penetration test, and it is now a standard part of pre-deployment review.

Automated red-teaming (Garak, PyRIT)

Scanners such as NVIDIA's Garak and Microsoft's PyRIT run hundreds of known injection and jailbreak probes against a model and report which succeeded, turning "is it vulnerable?" into a reproducible score you can re-run after every change.

Evaluation harnesses (Promptfoo, HackAPrompt data)

Promptfoo lets teams write injection test cases into CI so a build fails when a regression reopens a hole. Public corpora like the HackAPrompt dataset (600k+ adversarial prompts) supply realistic attacks to test against.

Emerging Vector: Tool-Description Poisoning (MCP)

As agents adopt shared tool protocols such as the , a new indirect surface appears: the tool description itself. A malicious or compromised tool server can hide instructions inside the natural-language description the model reads to decide how to call it, a "tool-poisoning attack." The description is data the model was never meant to obey, which is exactly the instruction/data boundary problem from Section 1, now relocated to the tool layer. Testing batteries increasingly include poisoned-tool scenarios for this reason.

The Unsolvability Debate

Is prompt injection fundamentally unsolvable?

The pessimistic position, stated explicitly by a national cybersecurity center and acknowledged by a major model provider: natural language processing and privilege separation are fundamentally incompatible. There is no equivalent of parameterized queries for natural language. The best achievable outcome is risk reduction, not elimination.

The optimistic position, supported by recent research: architectural modifications can create meaningful separation between instructions and data at the embedding level. One approach applies to data embeddings, creating architecturally distinct representations without additional parameters or performance loss. This was accepted at ICLR 2025 (top-ranked venue).

The current professional consensus sits between these positions: prompt injection is a persistent operational risk requiring layered mitigations. It is not a problem awaiting a single solution, and it is not a reason to avoid LLM deployment. The challenge is deploying responsibly under known, managed risk.

Common Misconceptions

"The OWASP Top 10 is a permanent classification." The 2023 and 2025 editions differ noticeably. Two categories were added, five were renamed. The framework reflects current consensus, not permanent truth. The valuable skill is applying whatever version is current, not memorizing a fixed list.

"Input filtering is sufficient defense." Filtering catches obvious patterns but is trivially bypassed by rephrasing, encoding, or indirect delivery. Effective defense is layered. If the entire defense strategy is "block messages containing 'ignore your instructions,'" the architectural vulnerability remains unaddressed.
