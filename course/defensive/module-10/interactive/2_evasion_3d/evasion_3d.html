The Optimization Behind an Adversarial Example

The model is fixed. Only the input changes. On the left the file is a point in the classifier's feature space; on the right it is a stack of bytes. The classifier reads every byte, so editing padding, which the CPU never runs, still shifts the point across the boundary and flips the verdict.

drag the left panel to rotate

Perturbing a photo only has to keep it recognizable. Perturbing malware has to keep it functional, a much tighter constraint. The attacker cannot scramble arbitrary bytes, because most changes corrupt the program, so the perturbation stays in regions that do not execute, such as padding or unused code caves. The file still runs and still does its work, but now a classifier that reads bytes calls it benign.
