1

The Alert Fatigue Problem

73% of organizations identify false positives as their #1 detection challenge (SANS 2025). This is not an abstract statistic. It describes a concrete operational failure mode: a detection system that catches "everything" generates so many false alarms that analysts drown in noise, burn out, and start ignoring alerts. Real attacks then slip through, not because the system missed them, but because the human stopped trusting the system.

The metrics in this page are the diagnostic instruments for this problem. They tell you not just whether a detection tool works, but how it fails and what those failures cost your team. You will need them every time you evaluate a vendor claim or tune a detection system.

2

The Confusion Matrix

Every classification outcome falls into one of four categories. In a security detection context:

Actually Malicious Actually Benign
System Flagged True Positive (TP)
Flagged alert, was real attack. System worked.		 False Positive (FP)
Flagged alert, was benign. Analyst wasted time.
System Passed False Negative (FN)
Didn't flag, was real attack. System failed silently. Worst case.		 True Negative (TN)
Didn't flag, was benign. Correct silence.

The cost asymmetry: cost analyst time and trust. cost breaches and data loss. But cost is context-dependent: missing a nation-state intrusion is not the same as missing a port scan.

3

Precision, Recall, and the Tradeoff

= TP / (TP + FP). "Of the alerts I fired, what fraction were real?"

= TP / (TP + FN). "Of the real attacks, what fraction did I catch?"

= 2 × (Precision × Recall) / (Precision + Recall), the harmonic mean, a single balanced metric.

The tradeoff: You cannot maximize both simultaneously. Tightening detection criteria raises precision but lowers recall, and you miss subtle attacks. Loosening criteria raises recall but craters precision, and analysts drown in noise.

This is the SOC analyst's daily reality. There is no universally correct setting, only a context-dependent decision that balances missed threats against wasted capacity.

Why Vendor Metrics Mislead

Precision and recall are properties of a model at a specific threshold and at a specific prevalence rate. Vendor test datasets are almost always attack-enriched (because you need attack samples to measure recall). A classifier showing 99% precision on a 50/50 test set may deliver less than 10% precision in your environment where only 0.1% of traffic is malicious. When a vendor reports one precision number, always ask: on what dataset, at what prevalence, and at what threshold?

Worked Example: Email Security Gateway

Your organization is evaluating an email security gateway. The vendor provides test results from 500 emails (200 phishing, 300 legitimate):

Actually Phishing Actually Legitimate
Flagged TP = 168 FP = 57
Passed FN = 32 TN = 243

Calculate, Then Extrapolate

Try this yourself first. Using the confusion matrix above, calculate precision, recall, and F1. Then extrapolate: if your organization processes 8,000 emails per day with a 3% phishing rate (240 phishing, 7,760 legitimate), how many legitimate emails get quarantined daily at this FP rate? How many analyst-hours does that consume if each quarantine review takes 2 minutes? Work through the numbers before revealing the solution.

Metrics from the test set:

  • Precision = 168 / (168 + 57) = 168 / 225 = 0.747 (74.7% of alerts are real)
  • Recall = 168 / (168 + 32) = 168 / 200 = 0.840 (84.0% of phishing caught)
  • F1 = 2 × (0.747 × 0.840) / (0.747 + 0.840) = 0.791

Extrapolation to 8,000 emails/day (3% phishing):

  • FP rate on legitimate email = 57 / 300 = 0.19 (19% of legitimate emails quarantined)
  • Legitimate emails quarantined daily = 7,760 × 0.19 = ~1,474 emails
  • Phishing emails missed daily = 240 × (1 - 0.84) = ~38 phishing emails reach inboxes
  • Analyst-hours for quarantine review = 1,474 × 2 min = 2,948 min = ~49 analyst-hours per day

The discovery moment: 49 analyst hours per day. If your SOC has 3 analysts working 8 hour shifts, you have 24 analyst hours available. The quarantine workload alone exceeds your team's entire capacity by 2x before they investigate a single real incident. This is how alert fatigue happens: not because the tool is bad (84% recall is reasonable), but because the false positive volume at organizational scale overwhelms the humans in the loop.
