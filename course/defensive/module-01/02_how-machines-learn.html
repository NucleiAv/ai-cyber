The AI Family Tree

When someone says "AI," they might mean anything from a hand-coded expert system to a billion parameter language model. The ambiguity is not just annoying. In security, it leads to misjudged risk assessments and vendor hype passing as technical evaluation. Before we go deeper, let's fix the vocabulary.

is the broadest umbrella: any system that performs tasks typically associated with human intelligence. Within that umbrella, terms are nested like layers:

1

Artificial Intelligence

The broadest umbrella: any system performing tasks that typically require human like reasoning. Expert systems, search algorithms, game engines, ML models.

2

Machine Learning (subset of AI)

Systems that learn patterns from data rather than following hand-written rules. Decision trees, SVMs, random forests, logistic regression, neural nets.

3

Deep Learning (subset of ML)

ML using neural networks with many layers. Learns hierarchical features automatically from raw data without manual feature engineering. CNNs for images, RNNs for sequences, Transformers.

4

Large Language Models (subset of DL)

Deep learning scaled to massive text data (trillions of tokens, billions of parameters). Generates and processes natural language via next-token prediction. GPT-4, Claude, Gemini, Llama.

Why This Matters for Security

When a vendor says their product uses "AI-powered threat detection," the term alone tells you nothing about how it works. A product using a decision tree to classify malware operates at the ML layer. A product using a transformer to analyze log narratives operates at the LLM layer. These have completely different data requirements, failure modes, and attack surfaces. Knowing which layer you're evaluating changes the questions you ask.

Here is the critical takeaway: each layer inherits the properties of the layers above it but adds new capabilities and new failure modes. An LLM is still doing machine learning; it just does it with a specific architecture (transformers), at a specific scale (billions of parameters), on a specific kind of data (text). Everything you learn about ML fundamentals applies to LLMs too.

What Is a Model?

A is simply a mathematical function that takes inputs and produces outputs. What makes it "machine learning" rather than regular programming is that the function's behavior is not written by a human. It is discovered from data.

Think of it this way. In traditional programming, a human writes the rules:

Traditional programming (pseudocode)
IF packet_size > 1500 AND destination_port == 4444:
    flag_as_suspicious()

In machine learning, the human provides examples, and the system figures out its own rules:

Machine learning (conceptual)
# Human provides:
#   1000 examples of normal traffic (labeled "benign")
#   1000 examples of attack traffic (labeled "malicious")
#
# Machine discovers:
#   Some internal function f(packet_features) → probability_of_attack
#
# The human never writes the detection rule.
# The model learns its own decision boundary from the examples.

The model's internal numbers, called or weights, encode what the model has learned. A simple spam filter might have a few hundred parameters. A malware classifier might have millions. GPT-4 has over a trillion. More parameters generally means the model can capture more complex patterns, but also means it needs more data to learn well and more compute to run.

A Model Is Not a Brain

Despite marketing language, ML models do not "think," "understand," or "know" things. They are mathematical functions that detect statistical patterns in their training data and apply those patterns to new inputs. This distinction matters in security: a model that "detects malware" is really saying "this input is statistically similar to inputs that were labeled malicious in training." If the training data was incomplete or biased, the model's decisions inherit those gaps.

is the process where the model's parameters get adjusted so that its outputs improve. The intuition is simple: show the model an example, check if it got the answer right, and nudge its internal numbers in a direction that makes it less wrong next time. Let's make this concrete with a cybersecurity example. Imagine you are training a model to classify network connections as either "normal" or (command-and-control communication):

  1. Collect data: You gather 50,000 network flow records. Security analysts label 2,000 of them as confirmed C2 traffic, the rest as normal.
  2. Feed the model: The model receives features for each connection (packet size, timing intervals, destination , bytes transferred, protocol) and attempts to predict "C2" or "normal."
  3. Measure error: For each prediction, the system computes how far off the model was. A confident wrong answer produces a large error signal; a correct answer produces almost none.
  4. Update weights: The model's parameters are nudged so that next time it sees a similar connection, it is slightly more likely to get it right.
  5. Repeat: This cycle runs for dozens of complete passes through the dataset (called ). With each pass, the model's internal decision boundary becomes more refined.

After training, the parameters are frozen. The model no longer changes and is now ready to be deployed.

The Cardinal Rule

A model can only learn what its training data contains. If your labeled dataset has no examples of a particular attack technique (say, DNS tunneling), the model will not detect it, no matter how many parameters it has. This is why training data quality is the single most important factor in ML system performance, and why security teams must continuously update and expand their training sets as the threat landscape evolves.

Knowledge Check

A security vendor tells you their malware classifier was trained on 100,000 samples collected between 2020 and 2022. It is now 2026. Without retraining, what is the most likely operational impact?

Inference: Using What Was Learned

is the deployment phase: running the trained model on new, real world data to get predictions. If training is like studying for an exam, inference is taking the exam. The model applies what it learned to inputs it has never seen before.

In the C2 detection example from Section 3, inference looks like this: a live network connection arrives, the model extracts the same features it was trained on (packet size, timing, destination reputation, etc.), runs them through its frozen parameters, and outputs a probability, say, "87% likely C2 callback." A threshold then converts that probability into an action: alert the SOC analyst, block the connection, or log for later review.

The distinction between training and inference matters operationally:

Training Phase

When: Before deployment (offline).

Compute: Expensive, hours to weeks on specialized hardware (GPUs/TPUs).

Data: Requires large, labeled datasets.

Security concern: Training data poisoning. An adversary who corrupts your training data corrupts the model's future decisions.

Inference Phase

When: Real time, during operations.

Compute: Fast, milliseconds per prediction on standard hardware.

Data: Processes one input at a time (or small batches).

Security concern: Evasion attacks. An adversary who understands the model's decision boundary can craft inputs that slip past it (adversarial examples).

Knowledge Check Your organization's email security gateway uses a deep learning model to detect phishing. An attacker discovers that adding specific invisible Unicode characters to the email body causes the model to classify phishing emails as benign. Which phase of the ML lifecycle is the attacker exploiting?

Machine Learning vs. Deep Learning

You will hear "machine learning" and "deep learning" used interchangeably in vendor pitches. They are not the same thing. Understanding the difference helps you evaluate whether a product's claims are reasonable for the problem it claims to solve.

Traditional Machine Learning

How it works: A human engineer selects and designs the features (packet size, connection duration, byte ratio, etc.). The model learns which combinations of these features matter.

Best for: Tabular data, structured logs, smaller datasets, situations where you need to explain exactly why the model made a decision.

How it works: The model learns its own features directly from raw data through multiple layers of neural network processing. No human feature engineering required.

Best for: Unstructured data (images, text, raw bytes), massive datasets, problems where human designed features cannot capture the relevant patterns.

Security example: A that classifies malware by converting raw binary files into grayscale images and learning visual patterns that distinguish malware families.

The Tradeoff

Deep learning can discover patterns that humans would never think to look for, but it requires far more data and compute, and its decisions are harder to explain. In regulated security environments where you must justify why an alert fired, traditional ML's interpretability can be more valuable than deep learning's raw accuracy.
