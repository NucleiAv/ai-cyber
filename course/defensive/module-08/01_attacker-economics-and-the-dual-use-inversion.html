Learning Objectives

By the end of this section, you will be able to:

  • Assess how AI shifts an attack along four levers: skill, cost, time, and scale.
  • Analyze a reported offensive use of AI by identifying which lever moved most, and by how much.
  • Explain the dual-use inversion: why every defensive AI capability has an offensive mirror image.

Read this before you begin

Everything in this module is for defense. We analyze how attackers use AI so we can detect and stop it. We will not build attack tools, write deliverable phishing, or run anything against real systems or people. All hands-on work uses simulated or pre-recorded data. Unauthorized scanning, intrusion, or impersonation is illegal in most jurisdictions regardless of the tool used. The goal throughout is analytical: study how offensive AI works so that defensive decisions improve.

Driving Question

How does AI actually change an attack, and how should a defender reason about that change without getting swept up in tool names that will be outdated by next semester?

1

From the Defender's Desk to the Attacker's

So far we have used AI as a defender: triaging alerts in the SOC, summarizing advisories for threat intelligence, reviewing code for vulnerabilities. Now we turn the same technology around and ask how adversaries use it. Earlier in the course we saw that generative AI lowers barriers, compresses timelines, and opens novel attack surfaces. The $11 voice clone showed that some attacks are already economically viable that were not before. This module gives us a framework to reason about those shifts precisely.

The temptation is to treat "AI for attackers" as a list of frightening new powers, but that framing fails quickly. Specific tools become obsolete within a semester, and a list of scary capabilities encourages two equally wrong reactions: panic ("attackers can now do anything") and dismissal ("it is all hype"). Neither produces a defensible resource decision.

A more durable approach is to ask one question of any reported use of AI by an attacker: which lever did this move, and by how much? Tool names change; the way AI reshapes the cost structure of an attack does not.

2

Four Levers: Skill, Cost, Time, Scale

These four terms describe the resources an attack consumes. We will use them for the rest of the module. Hover or focus the highlighted terms below to see their glossary definitions.

The expertise an attacker needs. AI lowers this when it can do something a human used to have to know: for example, writing fluent, context-appropriate text in a language the attacker does not speak, or generating working exploit code from a vulnerability description.

Cost

Money and infrastructure. AI lowers this when a task that needed paid specialists or custom tooling can be done with a subscription or an open-weight model. The $11/month voice-clone service we saw earlier in the course is a direct example.

Time

How long an operation takes from start to result. AI compresses this when it can summarize, draft, or triage faster than a person. CrowdStrike reported that average breakout time is now 29 minutes, with the fastest observed at 27 seconds.

Scale

How many targets one operator can reach. AI multiplies this when output that was once handcrafted per target (a tailored phishing lure, a customized pretext) can be generated automatically for thousands of recipients.

These levers move independently and unevenly. A given use of AI might collapse the skill floor while barely changing the time per attack, or the reverse. Saying "AI makes attacks easier" hides the distinctions a defender needs in order to decide where to spend limited resources. The four-lever question ("which lever moved, and by how much?") is what we will apply to every case in this module.

Let's put the lever model into quick practice. Each scenario below describes an attack that existed before AI. Read the "Before AI" baseline for each lever, then rate how much the introduction of AI shifted it. The question is not "how hard is this attack?" , it is "how much did AI change it?"

Why the lever model matters for defense budgets

Defensive budgets are finite. If we assume AI uniformly supercharges all attacks, we spread resources thinly and defend nothing well. If instead we can say that AI mostly collapses the skill and scale levers for social engineering while barely touching the time lever for complex intrusions, we can argue for concrete priorities: invest in phishing-resistant processes and identity verification before investing against fully autonomous hacking that does not yet exist at scale.

3

The Criminal AI-Tooling Market

A practical illustration of the skill and cost levers is the emergence of "dark" or jailbroken language models marketed to criminals. Tools using names like WormGPT and FraudGPT have been sold on underground forums since 2023, sometimes on a subscription basis, and a refreshed WormGPT variant was reported by in late 2025. The sales pitch from these marketplaces is : a person who cannot write convincingly, or cannot code well, may be able to get a usable first draft.

Rather than just noting these tools exist, walk the levers to see which ones actually moved.

LeverMovementWhy
Skill Sharply lowered Those with weak language and coding skills can produce plausible lures or script drafts. This is the lever that moves most.
Cost Moderately lowered A subscription replaces hiring a skilled collaborator, though it is not free and the better tools cost real money.
Time Somewhat lowered The drafting step gets faster, but the rest of an operation (infrastructure, delivery, monetization) is unchanged, so end-to-end time moves less than headlines imply.
Scale Increased, but bounded Content generation scales, but only as far as the attacker's delivery infrastructure allows.

The skeptic's check

Now apply the other half of the analysis. Independent research on the underground market finds that many advertised "dark LLM" tools are thin wrappers around legitimate models, or outright scams aimed at other criminals, and that the genuine capability is often overstated. 's "Hype vs. Reality" report documented that much of the criminal AI-tooling market is itself fraud.

The honest reading is layered: the skill and cost levers really did move, the scale and time levers moved less, and some of the marketing is itself fraud. A single verdict ("game-changer" or "all hype") misses the picture. A lever-by-lever reading does not.

Common misconceptions

  1. "AI changes everything about an attack equally." It does not. The levers move unevenly, and defensive spending should target the ones that actually moved.
  2. "If a criminal tool is advertised, it works as advertised." Underground marketing is often fraudulent or exaggerated. Always apply the skeptic's check.

One domain we scope out, on purpose

One well-documented real use of AI by threat actors is influence operations and disinformation, in which AI scales the production of fake personas and persuasive content across languages. This is probably the clearest "scale" example of attacker economics. This module treats it at awareness level only and focuses on intrusion-style and social-engineering attacks; a full treatment of influence operations belongs to a dedicated course or elective.

4

The Dual-Use Inversion

We have talked about earlier in the course. Let's work to solidify this. Every defensive capability we have built so far has an offensive mirror image:

Defensive Use (what we built)Offensive Mirror Image
Summarize an advisory into a CISO briefing Summarize a target's public profile into a spear-phishing pretext
Explain a vulnerability in a code review Explain a vulnerability to an attacker planning exploitation
Extract IoCs from a threat report Extract an organization's defensive signatures to evade them
Draft incident-response communications Draft convincing social-engineering lures at scale

The underlying model is the same. The text-generation capability that makes a language model useful for defense is exactly the capability an attacker repurposes. An analyst who can name precisely which defensive skill has an offensive twin, and what that twin implies for defensive priorities, is in a far better position than one who says "AI is a threat" and stops there.

Misconception

"Offensive AI and defensive AI are different technologies." They are the same capability pointed in different directions. Forgetting this leads us to underestimate how cheaply the tools we build for defense can be repurposed for offense.
