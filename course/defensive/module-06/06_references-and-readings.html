Academic Papers & Preprints

  • Ding, Y., et al. (2025). "Vulnerability Detection with Code Language Models: How Far Are We?" ICSE 2025. Paper
    Introduces PrimeVul, a de-duplicated vulnerability benchmark. Shows that prior datasets had low label accuracy (25% of BigVul's "vulnerable" functions were actually vulnerable) and train/test duplication, and that measured performance collapses on a relabeled, de-duplicated, chronologically split benchmark. Foundation for Section 1's LLM analysis mechanism and Section 2's dataset quality discussion.
    doi.org/10.1109/ICSE55347.2025.00038
  • Perry, N., et al. (2023). "Do Users Write More Insecure Code with AI Assistants?" ACM CCS 2023. Paper
    Controlled experiment showing developers using AI code assistants produced less secure code while believing it was more secure. Source for the overconfidence finding in Section 2 and the trust calibration framework in Section 5.
    doi.org/10.1145/3576915.3623157
  • Ladisa, P., et al. (2023). "A Taxonomy of Attacks on Open-Source Software Supply Chains." IEEE S&P 2023. Paper
    Systematic taxonomy of supply chain attack vectors: dependency confusion, typosquatting, maintainer compromise, and build system compromise. Structural framework for Section 4.
    doi.org/10.1109/SP46215.2023.10179304
  • Spracklen, J., et al. (2025). "We Have a Package for You! A Comprehensive Analysis of Package Hallucinations by Code Generating LLMs." USENIX Security 2025. Paper
    Code-generating models recommend nonexistent packages at 5–22% rates. When the same prompt is re-run ten times, 43% of hallucinated names appear in every single run, and 58% appear more than once. That predictability enables "slopsquatting" attacks. Source for Section 4's AI-specific supply chain vector.
    USENIX Security '25
  • Hu, E. J., et al. (2022). "LoRA: Low-Rank Adaptation of Large Language Models." ICLR 2022. Paper
    Low-rank adaptation technique for efficient fine-tuning. Foundation for Section 5's instruction/completion pair construction exercise.
    arXiv:2106.09685
  • Mitropoulos, D., et al. (2026). "Measuring and Exploiting Contextual Bias in LLM-Assisted Security Code Review." Preprint
    Demonstrates that adversarial PR metadata can bias LLM-based vulnerability detection, reducing critical evaluation. Cited in Section 2's confirmation bias discussion. Not peer-reviewed.
    arXiv:2603.18740
  • "Friends or Foes? Combining Static Analysis Tools and LLMs for Vulnerability Detection." ITEQS 2026 workshop (co-located with ICST 2026). Paper
    Reports F1 improvements of 17-60% when combining LLM review with traditional SAST tools for SQL injection detection. Cited in Sections 1, 3, and 5.
    conf.researchr.org/details/icst-2026/iteqs-2026-papers

Case Studies & Incident Reports

All four case studies are used in Section 4's supply chain attack timeline and the attack/defense matching exercise.

  • event-stream (2018). Incident
    Maintainer handoff attack: a new maintainer added a malicious dependency targeting cryptocurrency wallets. npm security team advisory; CERT/CC VU#534320.
  • Birsan dependency confusion (2021). Incident
    Researcher demonstrated dependency confusion attacks against Apple, Microsoft, and Tesla by publishing public packages that shadowed internal package names.
    Birsan, A. "Dependency Confusion: How I Hacked Into Apple, Microsoft and Dozens of Other Companies." Medium, February 2021.
  • Codecov (2021). Incident
    Build system compromise: attacker modified the Bash Uploader script to exfiltrate CI/CD environment variables including credentials. Codecov post-mortem, April 2021; Rapid7 analysis, May 2021.
  • 3CX (2023). Incident
    Cascading supply chain attack: compromise of Trading Technologies software was used to compromise 3CX's build environment, distributing trojanized desktop clients.
    Mandiant (Google Cloud blog, April 2023); CrowdStrike (March 2023).

Source Caveats

Reading Sources Critically

Every source has a context. When you read security research, keep these caveats in mind:

Source CategoryKey Caveat
Tool documentation (Semgrep, CodeQL) Describes tool capabilities accurately but does not assess limitations or compare against competitors objectively
Vendor statistics (Sonatype) Sonatype sells supply chain security products; statistics may reflect methodology that favors larger numbers. Treat vendor-sourced figures as directional, not authoritative
Academic preprints (arXiv:2603.18740) Not peer-reviewed; treat claims with appropriate caution
Government guidance (NCSC UK, CISA, NIST) Authoritative for policy context but may not reflect the latest empirical findings
Incident reports (event-stream, Codecov, 3CX) Post-incident analysis; details may be incomplete where investigations are ongoing or where affected parties limited disclosure
Benchmark results (PrimeVul, any tool evaluation) Always specify: which dataset, which model, what conditions. Benchmark performance does not equal production performance
