Vulnerability Missed
A SQL injection vulnerability spans 3 files: untrusted input enters in routes.py, passes through utils.py, and reaches a dangerous function in db.py.
routes.py Source
@app.route('/q') def search(): q = request .args.get('q') return find(q)
utils.py Passthrough
def find(term): cleaned = term .strip() return query_db( cleaned)
db.py Sink
def query_db(val): sql = "SELECT *" + " WHERE n='" + val + "'" db.engine .execute(sql)

Visible to LLM

Outside the Window

The dangerous execute() call in db.py. The LLM cannot see where this data ends up.
Chunk 1: The LLM sees the source but not the sink. It knows untrusted data enters via request.args.get(), but cannot see that this data eventually reaches a dangerous execute() call in db.py. The vulnerability is invisible from this chunk alone.
