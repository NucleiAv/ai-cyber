Reversing the Direction

This section completes the OWASP thread by reversing the direction: instead of classifying attacks after they happen, we assess defenses before they are tested. Section 6 then surveys AI applications in cybersecurity defense. Both share a method: pair every capability claim with its documented limitation.

Thread 3: OWASP as Defensive Checklist

In the attacks modules, we used the as a classification instrument: given an attack, identify which category it targets. That skill organizes knowledge and enables communication across teams. Now we reverse it. Given a deployment, we ask: for each OWASP category, what controls does this system have, and where are the gaps? This is the , using the same framework to evaluate defenses rather than classify attacks.

This reversal, from reactive ("what category was this attack?") to proactive ("what attacks are we not prepared for?"), is how security teams use the OWASP Top 10 when assessing real systems.

The Assessment Methodology

Classification asks "what happened?" Assessment asks "what could happen, and are we ready?" The methodology below gives a repeatable process for answering that second question. For each relevant OWASP category, walk through four steps:

  1. 1

    Applicability assessment

    Not every OWASP category applies to every deployment. A chatbot with no tool access faces LLM06 () differently than a system with API integrations. Start by determining which categories are relevant to this specific architecture.

  2. 2

    Existing controls identification

    For each applicable category, identify what controls the deployment currently has in place. Be specific: "input validation" is too vague; "regex-based keyword filtering on user input with a blocklist of 47 known injection patterns" is assessable.

  3. 3

    Gap analysis

    For each applicable category, identify what controls are missing or insufficient. The / distinction from Section 1 is useful here: a probabilistic control with known degradation under distribution shift is a different kind of gap than a completely absent control.

  4. 4

    Mitigation recommendation

    For each gap, recommend specific, implementable controls. Recommendations should be prioritized by risk (likelihood and impact) and feasibility (cost, complexity, timeline).

Assessment Lab: MedAssist

MedAssist is a patient-facing AI assistant for a regional healthcare network. It uses to answer patient questions about symptoms, medications, and procedures from the hospital's medical knowledge base. It integrates with a scheduling API to book and modify appointments. It uses application-level metadata filtering to restrict responses to patient-appropriate content, and it handles about 2,000 patient interactions per day.

Apply the four-step methodology to MedAssist across all ten OWASP LLM Top 10 (2025) categories. For each category, you will decide whether it applies to MedAssist's architecture, identify existing controls, find gaps, and rate the risk priority. The assessment is deployment-specific: your answers should reflect MedAssist's particular architecture, not generic LLM risks.

Reference: OWASP Top 10 for LLM Applications (2025)

The full list of categories, descriptions, and recommended mitigations is maintained by OWASP. Keep it open as you work through the assessment below.

Every identifier in this course is from the 2025 edition. OWASP revises the list periodically, and entries move position, merge, or get renamed between releases, so a bare number is ambiguous. The failure modes are the durable part; the numbering is not. Name the edition whenever you cite one, and confirm the current release before putting a number in front of a stakeholder.

The assessment is deployment-specific. MedAssist's scheduling API access makes LLM06 high priority; a chatbot without tool access would deprioritize it. The metadata filtering gap in LLM08 is specific to MedAssist's architecture; a system with database-level isolation would have a different gap profile entirely. When you assess a different system, the same methodology applies, but the answers change.
