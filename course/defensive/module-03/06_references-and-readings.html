Academic Papers & Preprints

  • Schulhoff, S., et al. (2024). "The Prompt Report: A Systematic Survey of Prompting Techniques." Preprint
    Comprehensive taxonomy of prompt-engineering techniques. Used for vocabulary and structural framework in Section 1.
    arXiv:2406.06608
  • Sclar, M., et al. (2024). "Quantifying Language Models' Sensitivity to Spurious Features in Prompt Design." ICLR 2024. Paper
    FormatSpread study: non-semantic prompt changes (separators, casing, whitespace) moved accuracy by up to 76 percentage points. Source of the brittleness evidence in Section 2.
    arXiv:2310.11324
  • Lu, Y., et al. (2022). "Fantastically Ordered Prompts and Where to Find Them: Overcoming Few-Shot Prompt Order Sensitivity." Paper
    Demonstrates that the order of few-shot examples alone can swing accuracy by tens of points.
    arXiv:2104.08786
  • Zhao, Z., et al. (2021). "Calibrate Before Use: Improving Few-Shot Performance of Language Models." Paper
    Documents few-shot instability and proposes calibration methods.
    arXiv:2102.09690
  • Wang, X., et al. (2023). "Self-Consistency Improves Chain of Thought Reasoning in Language Models." Paper
    Aggregating multiple sampled answers improved reasoning benchmark performance by ~18 points. Foundation for the "measure across runs" discipline in Sections 2–3.
    arXiv:2203.11171
  • Wei, J., et al. (2022). "Chain-of-Thought Prompting Elicits Reasoning in Large Language Models." Paper
    Chain-of-thought reasoning gains emerge at scale (~60B+ parameters). Cited for the CoT scale-dependence caveat in Section 2.
    arXiv:2201.11903
  • Liu, N.F., et al. (2024). "Lost in the Middle: How Language Models Use Long Contexts." Paper
    Models use information at the start and end of long prompts more reliably than information in the middle.
    arXiv:2307.03172
  • Alam, M., et al. (2024). "CTIBench: A Benchmark for Evaluating LLMs in Cyber Threat Intelligence." Paper
    Cyber-threat-intelligence tasks including the difficulty of CVSS prediction from descriptions.
    arXiv:2406.07599
  • "From Description to Score: Can LLMs Quantify Vulnerabilities?" (2025). Preprint
    Demonstrates that CVSS scoring from vulnerability descriptions is inherently challenging and that models systematically misclassify.
    arXiv:2512.06781
  • Spracklen, J., et al. (2025). "We Have a Package for You! A Comprehensive Analysis of Package Hallucinations by Code Generating LLMs." USENIX Security Symposium. Paper
    Code-generating models recommend nonexistent packages at 5–22% rates; 58% of hallucinated names recur, enabling supply-chain attacks ("slopsquatting").
    USENIX Security '25
  • Willard, B. & Louf, R. (2023). "Efficient Guided Generation for Large Language Models." Preprint
    Theory behind constrained and guided decoding for structured output.
    arXiv:2307.09702
  • AI-Augmented SOC Survey & CORTEX. (2025). Preprint
    Operational context for SOC false-positive rates and production-readiness judgment.
    arXiv:2510.00311

Government Sources

  • National Vulnerability Database (NVD). Government
    The authoritative U.S. government database of CVE records and their CVSS scores. The primary cross-reference for verifying model-generated vulnerability identifiers.
    nvd.nist.gov
  • CISA Known Exploited Vulnerabilities (KEV) Catalog. Government
    A U.S. government list of vulnerabilities confirmed to be actively exploited. Used to verify exploitation claims in model output.
    cisa.gov/known-exploited-vulnerabilities-catalog

Practitioner & Institutional Resources

  • Hugging Face. Chat Templates. Reference
    Explains how different model families serialize roles (system, user, assistant) into the token sequence the model receives.
    huggingface.co/docs/transformers
  • JSON (JavaScript Object Notation). Data Format
    Reference and specification for the structured-output format used throughout Section 4.
    developer.mozilla.org JSON · json.org
  • Vendor prompting guides. Tool Docs
    The structure taught in this module transfers across model families; the tuning advice does not. Each vendor publishes guidance for its own models, kept more current than any course can be. Consult the one for the model you are running.
    Anthropic, prompting best practices · OpenAI, prompt engineering · Google, Gemini prompt design · Meta, Llama prompting
    If a link fails, search the vendor's developer documentation rather than trusting a third-party copy.
  • Structured output / constrained decoding. Tool Docs
    Consult the documentation for the runtime you use. The feature is variously called structured outputs, JSON mode, or grammar-constrained decoding. Some runtimes accept a JSON schema directly; others use a grammar format.

Source Caveats

Reading Sources Critically

Every source has a context. When you read security research, keep these caveats in mind:

Source CategoryKey Caveat
Preprints (The Prompt Report; From Description to Score; Willard & Louf; AI-Augmented SOC Survey) Not peer-reviewed. Several are surveys or position pieces rather than controlled studies. Read the methodology before treating any number in them as a result.
Prompting results (Sclar et al.; Lu et al.; Zhao et al.; Wei et al.) Prompting findings date quickly. Effects such as format sensitivity, few-shot order sensitivity and the scale threshold for chain-of-thought were measured on model generations that have since been replaced. Reproduce on your own model before designing around them.
Benchmarks (CTIBench, FormatSpread) A benchmark measures performance on that benchmark. Scores can be inflated by training-data contamination, and benchmark tasks are cleaner than production ones.
Runtime and vendor documentation (Hugging Face chat templates, constrained decoding) Changes without notice and differs by library version and model family. Verify against the version you have installed rather than the version the documentation assumes.
Government vulnerability data (NVD, CISA KEV) Enrichment lags disclosure, and coverage is uneven. A missing CVSS score means the record has not been enriched, not that the vulnerability is harmless.
Standards (OASIS STIX 2.1) Versioned. Producers and consumers can support different versions and different optional properties, so conformance is a range rather than a yes or no.
