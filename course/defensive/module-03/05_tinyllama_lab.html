Lab: Requested vs. Schema-Layer Output

Four pre-built prompts, each with its own frustrations. Run them through two paths and see which one breaks first. The failures are the lesson.

~20 min lab + ~15 min transcript In-browser interactive

Learning Objectives

By the end of this lab, you will be able to:

  • Predict which path (requested JSON vs. schema-layer JSON) will break on a given input, and explain why the failure was structural rather than accidental.
  • Explain why the schema-layer path produces consistent, parseable output even when the model's raw signal is messy or ambiguous.
  • Spot fabricated data inside structurally valid JSON by tracing identifiers back to the source evidence.

About this lab

We have built four curated prompts, each designed to surface a specific failure mode. Some will break in obvious, frustrating ways. Others will look fine until you check the evidence. A small language model (TinyLlama, ~1B parameters) runs entirely in your browser using WebGPU or WASM, so nothing leaves your machine. Try every example through both paths. The interesting part is not the correct outputs; it is the consistent patterns in how each path fails, and how the schema layer recovers where the raw request cannot. The first load downloads the model from Hugging Face and may take several minutes. Subsequent loads use the browser cache.

Accessibility update: The prompt display boxes now have improved scrollbars that are easier to see and use. The display height has been increased to 500px to reduce scrolling needs.

Note on prompt structure: The prompts shown throughout this lab intentionally end with labels like "JSON:" or "LABEL:" because these are the points where the model is supposed to provide its response. The model's actual output appears in a separate display box below the prompt, labeled "Raw model output" or "Model signal." This is by design: the prompt shows what the system asks the model, and the output box shows what the model returns.

If you continue to experience difficulty viewing the prompts or understanding the layout, please contact the course instructor.

Static Transcript of the Lab

The lab above downloads a model and runs it in your browser, and that can fail: no WebGPU, a blocked download, a slow connection, a locked-down machine. The lesson does not depend on it. Below is the full transcript of all four cases, both paths, with the prompts as they are sent and the outputs each path typically returns. Read it instead of running the lab, or read it afterwards to check what you saw.

About these outputs

Path A output varies between runs, so treat the raw text below as representative of the failure mode rather than as the exact string you will see. Path B output does not vary in shape, because the browser builds the object rather than the model. Where your run differs, the interesting question is which of the four checks moved.

Establishes the baseline. Both paths usually agree here, which is what makes the later cases legible.

Read this one carefully, because it is the limit of the technique. The schema layer guarantees shape, not judgment. It cannot tell that the label is the attacker's choice rather than the analyst's. Structure is a parsing defense, not a content defense, and no output contract will fix an input you did not isolate.

What the four cases add up to

  • Case 1 shows both paths succeeding, which is why an easy test case cannot tell you a path is safe.
  • Case 2 separates being right from being parseable. The model had the correct label and still failed the contract.
  • Case 3 separates valid from correct. Well-formed JSON carried a wrong IP, and only checking the value against the evidence caught it.
  • Case 4 marks the boundary of the whole technique. The schema layer enforces shape and has no opinion about truth, so an injected instruction produces a clean, confident, auto-suppressible, wrong answer through both paths.

Taken together: constrained output solves a parsing problem completely and a trust problem not at all. Keep the two in separate columns of your playbook.
