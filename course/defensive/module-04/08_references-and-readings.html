Recommended Readings

Complete these readings at the indicated points in the module. Total reading time is approximately 35 minutes.

R1: SOC Alert Triage Process (Pre-Reading)

Title: "Alert Triage Process: The Complete SOC Analyst's Guide"
Author: CyberDefenders (2025)
URL: cyberdefenders.org/blog/alert-triage-process/
Reading time: ~15 minutes
When to read: Before starting this module

This practitioner guide establishes the SOC triage workflow that frames all hands-on activities. It describes the five-stage triage model, severity classification practices, and the 15-30 minute per-alert time pressure that motivates AI-assisted triage.

R2: ROC Curves and AUC (Before Section 6)

Title: "Classification: ROC and AUC" (Machine Learning Crash Course)
Author: Google Developers
URL: developers.google.com/machine-learning/crash-course/classification/roc-and-auc
Reading time: ~10 minutes
When to read: Before starting Section 6

Clear, visual explanation of ROC curves and AUC with interactive examples. Extends the precision/recall vocabulary from Module 1 into the continuous tradeoff space.

R3: UNSW-NB15 Dataset Overview (Before Section 3)

Title: "The UNSW-NB15 Dataset" (project page)
Author: UNSW Sydney
URL: research.unsw.edu.au/projects/unsw-nb15-dataset
Reading time: ~10 minutes
When to read: Before starting Section 3

Introduces the dataset features used in the feature-engineering thought experiment. Includes feature descriptions, attack category definitions, and dataset provenance.

Academic Papers & Preprints

Key citations referenced in this module's content.

  • Moustafa, N., and Slay, J. "UNSW-NB15: A Comprehensive Data Set for Network Intrusion Detection Systems." Military Communications and Information Systems Conference (MilCIS), IEEE, 2015. Paper
    Defines the UNSW-NB15 dataset: 49 flow features in documented categories, 9 attack types. The feature schema used throughout Section 3.
    UNSW-NB15 Dataset Project
  • Engelen, G., et al. "Troubleshooting an Intrusion Detection Dataset: the CICIDS2017 Case Study." Workshop on Traffic Measurements for Cybersecurity (WTMC), 2021. Paper
    Documents feature-extraction errors and contradictory labels in CIC-IDS2017; the basis for Section 3's benchmark-literacy discussion.
    PDF (KU Leuven)
  • "A Comparative Analysis of Supervised and Unsupervised Models for Detecting Attacks on the Intrusion Detection Systems." Information, MDPI, 14(2):103, 2023. Paper
    Supervised vs. unsupervised IDS comparison cited in Section 3's detector-comparison grid.
    mdpi.com/2078-2489/14/2/103
  • "Leveraging Large Language Models for Scalable and Explainable Cybersecurity Log Analysis." Journal of Cybersecurity and Privacy, MDPI, 5(3):55, 2025. Paper
    LLM log-analysis capabilities and limits informing Sections 1 and 2.
    mdpi.com/2624-800X/5/3/55
  • "The paradigm of hallucinations in AI-driven cybersecurity systems." Computers and Electrical Engineering, Elsevier, 2025. Paper
    Source for the Section 2 failure-mode taxonomy of LLM hallucinations in security contexts.
  • "Evaluation of Intrusion Detection Systems." Journal of Information Processing Systems, 2016. Paper
    Confusion-matrix and metrics methodology applied in Sections 2 and 4.
  • "Individual Packet Features are a Risk to Model Generalisation in ML-Based Intrusion Detection." 2024. Preprint
    Found packet-level features transfer poorly across networks; cited in Section 3 for flow-level aggregation. Not peer-reviewed.
    arXiv:2406.07578
  • "Benchmarking Large Language Models for Log Analysis, Security, and Interpretation." Journal of Network and Systems Management, Springer, 2024. Paper
    LLM log-analysis benchmark results referenced for Section 4's tool comparison.

Source Caveats

Reading Sources Critically

Every source has a context. When you read security research, keep these caveats in mind:

Source Category Key Caveat
Practitioner guides (R1) Represent current practices, not empirical evidence; may include tool-specific references
Educational resources (R2) General ML context; the module adds security-specific application
Dataset documentation (R3) Describes a specific dataset with known limitations; not representative of modern networks
Academic preprints (E2, E3, E7) Not peer-reviewed; treat claims with appropriate caution
Vendor documentation (E5, E8) Factual format documentation or roadmap material; note the vendor context
Benchmark results (any source) Always specify: which dataset, which model, what conditions. Benchmark performance does not equal production performance.
