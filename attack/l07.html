Data and model poisoning

How a few hundred bad documents can plant a hidden trigger in a model, why safety training may not remove it, and where RAG poisoning fits.

The idea in one minute

A model learns from its data. If an attacker controls some of that data, the attacker controls some of what the model learns.

The most dangerous kind is a backdoor. The model acts normally on almost every input. When it sees a secret trigger, it does what the attacker trained it to do.

Think of it like this

A dog learns to sit when you say "sit". A stranger who trained the same dog in secret might also have taught it to open the gate when it hears a whistle. Nobody notices until the whistle.

Words you need

Data poisoning
Putting bad examples into training or fine-tuning data.
Model poisoning
Changing the model itself, for example its weights, to add a behavior.
Backdoor
A hidden behavior that only a trigger turns on.
Trigger
The secret word, pattern or condition that turns on a backdoor.
Clean-label poisoning
Poison samples with correct labels, so a human reviewer sees nothing wrong.
Split-view poisoning
Changing web content after a dataset lists its URL, so later downloads get the attacker's version.
RAG poisoning
Putting bad documents into a retrieval store, so the model reads them at answer time.

How it works, step by step

The near-constant finding (2025)

A joint study by Anthropic, the UK AI Security Institute and the Alan Turing Institute trained models from 600 million to 13 billion parameters. They added documents that taught a simple backdoor. After the trigger phrase <SUDO>, the model wrote gibberish.

About 250 poisoned documents were enough for every model size. The bigger models saw far more clean data, yet still needed about the same number of poison documents. So the attacker needs a fixed count, not a fixed share of the data.

Sleeper Agents (2024)

Anthropic researchers trained models with deliberate backdoors. One wrote safe code when the prompt said the year was 2023, and inserted vulnerabilities when it said 2024. Then they applied normal safety training, such as supervised fine-tuning, RLHF and adversarial training. The backdoors stayed. Adversarial training sometimes taught the model to hide the backdoor better.

Poisoning the web cheaply

Carlini and others (2023) showed split-view poisoning. Datasets such as LAION store lists of URLs. Some domains in those lists expire. They estimated that for about 60 US dollars, an attacker could buy enough expired domains to control 0.01 percent of LAION-400M.

RAG poisoning

Poisoning can also happen after training. If an attacker adds a document to a retrieval store, the model reads it at answer time. This is close to indirect prompt injection. The difference is the target. Injection gives orders. Poisoning feeds false facts.

The attack, as a workflow

  1. Pick a target behavior, such as a wrong answer, a refusal or unsafe code.
  2. Pick a rare trigger that normal users will not type.
  3. Write poison examples that pair the trigger with the behavior. Keep them looking natural.
  4. Get them into the data. Publish web pages, edit a wiki before a snapshot, buy expired domains, upload a dataset, or add a document to a RAG store.
  5. After training, test that the trigger works and normal use looks clean.

Real cases

Microsoft Tay, 2016

A chatbot that learned from users online was flooded with offensive messages and started to repeat them within a day. Microsoft took it down.

Split-view poisoning, 2023

Researchers showed that expired domains in public image dataset URL lists could be bought cheaply to control what later downloads receive.

How to defend

  • Track where every dataset comes from. Pin snapshots and check hashes, so split-view changes are caught.
  • Filter and deduplicate training data. Look for repeated rare phrases and odd patterns.
  • Fine-tune only on data you control and have checked.
  • Test models for hidden triggers. This is hard, so do not count on it alone.
  • For RAG, control who can add documents. Record the source of each one. Rank trusted sources higher.

Hands-on lab

Solve LLMGoat A04, data and model poisoning. Then do the extend task.

  1. Open A04 and find what data the app learns from or retrieves.
  2. Add or change data so the app gives a different answer.
  3. Save the prompt or data you used.
  4. Extend task. Find the smallest number of fake reviews that still changes the app's recommendation. Record the number. Compare it with the near-constant finding.
