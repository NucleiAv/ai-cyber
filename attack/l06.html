Supply chain, signing and governance

How to prove a model is the one your pipeline approved. AI bills of materials, Sigstore signing, SLSA, and a deploy gate that blocks unsigned models.

The idea in one minute

Lesson 5 showed how a model can be swapped or poisoned. This lesson asks a governance question. How do you know what you run, and that nobody changed it?

Three tools answer it.

  • An AI-BOM lists every model, dataset and library in an AI system, with versions and sources.
  • Signing proves who produced a file and that it did not change.
  • Provenance records how the file was built, from which inputs, on which system.
Think of it like this

A sealed medicine box has an ingredient list (the BOM), a tamper seal (the signature) and a batch record from the factory (the provenance). You check all three before you take the pill.

Words you need

AI-BOM
AI bill of materials. A list of models, datasets, code and services in an AI system, with versions and sources.
Digital signature
A value made with a private key. Anyone with the public key can check that the file is unchanged and came from the key owner.
Sigstore
Free, open tools for signing software. cosign signs and verifies files and container images.
OCI registry
A server that stores container images and other files, such as a Docker registry.
Provenance
A signed record of how an artifact was built.
Transparency log
A public, append-only log of signatures. Sigstore's log is called Rekor.

How it works, step by step

Sign, store, verify, deploy

  1. The ML engineer or the training pipeline makes a key pair, or uses Sigstore keyless signing with a short-lived certificate.
  2. The model file is pushed to a registry with a version tag.
  3. cosign signs the stored artifact. The signature is stored next to it in the registry.
  4. At deploy time a gate runs cosign verify with the public key.
  5. If the check passes, the model is deployed. If it fails or there is no signature, the gate stops.

A signature proves integrity and origin. It does not prove the model is safe. A signed poisoned model is still poisoned. That is why provenance and the BOM matter too.

The tension in an AI-BOM

A detailed BOM helps security. You can find every system that uses a bad dataset. But listing exact training sources can expose a company in copyright disputes. Many companies list only broad sources, such as "Common Crawl", which helps very little for security.

How to defend

  • Keep an AI-BOM for every AI system. Include the model revision, its hash, the datasets and the libraries.
  • Sign every model your pipeline produces or approves. Verify the signature at every deploy.
  • Record provenance. Use a hosted build that writes signed provenance, as SLSA asks.
  • Watch your dependencies for change. A rug pull changes a trusted component after you approved it.

Hands-on lab

You act as the ML engineer who signs a model and as the deploy system that accepts only signed models. You need Docker, ORAS and cosign.

  1. Start a local registry. docker run -d -p 5000:5000 --name local-registry registry:2
  2. Make a dummy model. echo "dummy model weights" > model.pt
  3. Make a key pair. cosign generate-key-pair makes cosign.key and cosign.pub. Set a password.
  4. Push the model as v1. oras push localhost:5000/my-secure-model:v1 model.pt
  5. Sign v1. cosign sign --key cosign.key localhost:5000/my-secure-model:v1
  6. Push a second file as v2 and do not sign it.
  7. Write deploy.sh (below). Run it on v1 and on v2.
  8. Expected result. v1 prints SUCCESS. v2 prints BLOCKED.
  9. Extend task. Push new content to the v1 tag after signing. Run the gate again and confirm it blocks the changed model.
#!/bin/bash
REGISTRY_URI=$1
if [ -z "$REGISTRY_URI" ]; then
  echo "Usage: ./deploy.sh <registry-uri>"; exit 1
fi
if cosign verify --key cosign.pub --allow-insecure-registry "$REGISTRY_URI" > /dev/null 2>&1; then
  echo "SUCCESS: Signature verified. Proceeding with deployment."
else
  echo "BLOCKED: Artifact is unsigned or signature is invalid. Deployment halted."
  exit 1
fi
Hints, open only if stuck for 30 minutes
  • cosign 2.x uploads a signing record to the public Rekor log by default and asks you to confirm. For a fully private lab, sign with --tlog-upload=false and verify with --insecure-ignore-tlog=true.
  • A local registry on localhost uses plain HTTP, so verify needs --allow-insecure-registry.
  • cosign warns when you sign by tag. In real pipelines sign and verify by digest (the sha256 value), because a tag can move.
