Unbounded consumption, denial of wallet

LLMs cost money per token. Learn how attackers burn your budget, slow your service or copy your model, and why request limits alone do not stop them.

The idea in one minute

Every model call costs compute. Cloud APIs bill per token. So an attacker can harm you without stealing anything.

  • Denial of service. Make the model so busy that real users wait or fail.
  • Denial of wallet. Make you pay. A large bill is the damage.
  • Model extraction. Send many queries and train a copy from the answers.
Think of it like this

A restaurant that lets each guest order without limit can be closed by one guest who orders everything on the menu a hundred times. Counting guests at the door does not help. You must count what each guest orders.

Words you need

Token
A unit of text. APIs charge per input token and per output token.
RPM
Requests per minute. A common rate limit that counts requests, not cost.
Token bucket
A rate limit where each user has a budget of tokens that refills over time.
Sponge example
An input built to make a model use as much energy and time as possible.
Denial of wallet
An attack that drives up a pay-per-use bill.
LLMjacking
Using stolen credentials to run models at the victim's cost.

How it works, step by step

Why counting requests fails

Module 11 works the numbers for one leaked API key. The key allows 60 requests per minute, up to 200,000 tokens each, with no spending cap. Input costs 3 dollars per million tokens.

  1. 60 requests times 200,000 tokens is 12 million tokens per minute.
  2. 12 million tokens times 3 dollars per million is 36 dollars per minute.
  3. 36 dollars times 60 minutes times 24 hours is 51,840 dollars per day.

The key never broke its rate limit. The limit counted requests. The bill counted tokens.

Sponge examples

Shumailov and others (2021) built inputs that made neural networks use many times more energy and time per input, without changing the input size much. For LLMs, a simple sponge asks for the longest possible output, such as "repeat the word 'company' forever". Each request then runs to the maximum output length.

Fact check

The same "repeat a word forever" prompt has another effect. Nasr and others (2023) found that it made ChatGPT drift and print memorized training data. Lesson 4 covers that kind of leak.

The attack, as a workflow

  1. Find an endpoint or a key with no spending cap. Leaked keys in public code are common.
  2. Send requests that maximize tokens, such as long inputs and prompts that ask for endless output.
  3. Spread requests over many accounts or keys to stay under per-account limits.
  4. For agents, trigger loops, such as tasks that make the agent call tools again and again.

Real cases

LLMjacking, 2024

Sysdig reported attackers who used stolen cloud credentials to run hosted models at the victims' cost, and estimated over 46,000 dollars per day for one victim.

Operation Bizarre Bazaar

Pillar Security reported stolen access to AI endpoints resold on a marketplace.

How to defend

  • Limit tokens and cost, not only requests. Use a token bucket per user and per key.
  • Cap input size and set a maximum output length for every call.
  • Set per-key daily spending caps that alert and then stop.
  • Add timeouts and step limits for agents.
  • Alert on spikes in tokens per user and on many near-identical queries, which can signal model extraction.
  • Keep keys out of code. Rotate them, and scan repositories for leaks.

Hands-on lab

Solve LLMGoat A10. Then write a sponge prompt and measure it.

  1. Solve LLMGoat A10, unbounded consumption. Save the prompt.
  2. Write a sponge prompt that asks for the longest possible answer, or that takes long before the first token.
  3. Extend task. Run a normal prompt and your sponge prompt on a small local model with ollama run <model> --verbose. The verbose flag prints the time and token counts. Compare them.
Hints, open only if stuck for 30 minutes
  • Ollama prints eval count (tokens out) and total duration after each answer when you use --verbose.
  • Many apps cap output length. Look for a way to make the app call the model again, which multiplies cost.
