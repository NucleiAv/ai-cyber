Vector and embedding weaknesses

Embeddings are compressed text, not anonymous numbers. Learn how vectors leak, how attackers poison semantic search, and how to protect a RAG store.

The idea in one minute

RAG apps turn text into embeddings, lists of numbers that capture meaning. Similar meanings get nearby vectors. A vector database finds the nearest ones to a question.

Two wrong beliefs make this risky.

  • "Vectors are anonymous." They are not. Much of the original text can be rebuilt from a vector. This is embedding inversion.
  • "Search returns what is relevant." It returns what is near. An attacker can write a document built to be near many questions.
Think of it like this

An embedding is like a very detailed fingerprint of a sentence. Given the fingerprint and a good lab, you can often work out the sentence.

Words you need

Embedding
A list of numbers that represents the meaning of a text.
Vector database
A store that finds the vectors closest to a query vector, for example Pinecone, Milvus or pgvector.
Nearest neighbor search
Finding the stored vectors closest to the query.
Embedding inversion
Rebuilding the original text from its embedding.
Corpus poisoning
Adding documents to a store so they are retrieved for target questions.
Tenant
One customer in a system that serves many customers.
Homomorphic encryption
Encryption that allows some math on data while it stays encrypted.

How it works, step by step

Inversion

Vec2Text (Morris et al., 2023) trained a model that guesses text from an embedding, then corrects its guess step by step. For one common embedding model it rebuilt 92 percent of 32-token inputs exactly. The lesson reading by Chen et al. (2024) shows that inversion works across languages too. So a leaked vector store is close to a leaked document store.

Poisoning the search space

PoisonedRAG (Zou et al., 2024) added a few crafted texts for each target question to a store with millions of texts. The texts were close to the question and carried a false answer. The RAG system gave the attacker's answer in about 90 percent of cases in their tests.

Adversarial illusions (Zhang et al., 2024) works on multi-modal embeddings. A small change to an image or a sound can move its embedding next to any chosen target, such as a text label. Systems that trust the embedding then treat the input as something it is not.

Access control mistakes

Many teams put every customer's documents in one index and filter by tenant in the app. One missing filter leaks one customer's data to another.

The attack, as a workflow

  1. Learn what the store holds and who can add to it, such as uploads, a wiki, tickets or public web pages.
  2. Pick target questions.
  3. Write text that is close in meaning to those questions and carries the false answer or an instruction.
  4. Get it indexed.
  5. If you can read raw vectors, for example from an open database, try to invert them back to text.

Real cases

PoisonedRAG, 2024

A handful of crafted texts per question, placed in a store of millions, controlled most answers to those questions.

How to defend

  • Treat vectors as sensitive as the text they came from. Encrypt the store at rest, require authentication, and do not expose it publicly.
  • Filter retrieval by the user's permissions. Use separate indexes or namespaces for tenants.
  • Control who can add documents. Record the source of every chunk and check new content before indexing.
  • Watch retrieval logs. A document that appears for many unrelated questions is suspicious.
  • Prefer trusted sources in ranking, and show sources to users.
