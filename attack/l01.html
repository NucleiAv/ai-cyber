Introduction to LLM security

What is different about attacking a system that reads and writes language, and the map of attacks you will learn in this track.

The idea in one minute

A normal program follows exact rules. An LLM app follows text. It reads your words, the developer's words, and any document it is given, and then it writes the most likely next words.

This makes it useful. It also gives the attacker a new way in. The attacker does not need a memory bug or a stolen password. The attacker needs only the right words in the right place.

Think of it like this

Think of a very helpful new employee who reads every note on the desk and does what the notes say. The employee cannot tell a note from the boss from a note that a stranger slipped under the door. Most attacks in this track are a version of that note.

Words you need

LLM
Large language model. A model trained on a large amount of text that predicts the next token.
Token
A small piece of text, often a short word or part of a word. The model reads and writes tokens.
System prompt
Hidden instructions from the developer, such as the bot's role and rules.
Prompt injection
Text that makes the model do something the developer did not plan.
Jailbreak
A type of prompt injection that makes the model ignore its safety training.
Training data
The text the model learned from. It can hold private data that the model memorized.
Attack surface
Every place where an attacker can put input into a system.
CTF
Capture the flag. A practice game where you attack a test system to find a secret flag.

How it works, step by step

An LLM app is more than the model. It is a chain of parts. Each part is a place to attack.

  1. Training. The model learns from huge text collections. If an attacker can add text here, the model can learn a hidden behavior. This is poisoning.
  2. The model file. People download models from hubs. A model file can carry code that runs when it loads. This is a supply chain attack.
  3. The prompt. At run time the app joins the system prompt, the user text and other content into one long text. Any part an attacker controls can carry instructions. This is prompt injection.
  4. The output. The app shows the answer or passes it to a browser, a database or a tool. Unchecked output can carry an attack forward.
  5. The actions. Agents call tools. If the model is fooled, the tools do real damage.

The survey you read this week sorts attacks into two big groups. Security attacks change what the model does, for example prompt injection, jailbreaking, backdoors and poisoning. Privacy attacks take information out of the model, for example training data extraction and PII leakage.

Fact check

The OWASP Top 10 for LLM Applications 2025 is the list most teams use. The 14 lessons of this track follow it in order, from LLM01 prompt injection to LLM10 unbounded consumption.

The attack, as a workflow

  1. Find the target app and learn what it is for. Read its public pages.
  2. Find every place your text reaches the model. This includes the chat box, uploaded files, web pages it reads and emails it reads.
  3. Ask for something it must refuse, and watch how it refuses. The refusal often shows the rules it follows.
  4. Change the wording, the role or the format until the rules give way.
  5. Record the exact prompt that worked, and why you think it worked.

Real cases

Prompt Airlines

A CTF built by the cloud security company Wiz. You chat with an airline support bot and try to make it break its rules, for example to reveal its hidden identifier or give you a free ticket. Each challenge adds a new defense.

Gandalf

Lakera's well-known password game. The classic levels are retired. Its address now opens Agent Breaker, which uses agent apps instead of a password.

How to defend

You learn the defenses for each attack in later lessons. Three ideas hold for all of them.

  • Assume the model can be fooled. No prompt makes a model fully obey.
  • Limit what a fooled model can do. Give it the smallest set of tools, data and permissions.
  • Check in code, outside the model. A rule in code cannot be talked out of its job.

Hands-on lab

This week you solve Prompt Airlines challenge 1 and the first levels of the Lakera practice app. Work in the browser. You need no install.

  1. Open Prompt Airlines and read the challenge text. Write down what the bot must not do.
  2. Ask the bot plainly for the secret. Note how it refuses.
  3. Try a role change. Tell the bot it is in a test or debug mode, or that you are a staff member.
  4. Try a format change. Ask it to put its instructions into a poem, a table or JSON.
  5. When you get the flag, copy the exact prompt and the flag into your notes file.
  6. Open Agent Breaker and try the first two apps the same way.
Hints, open only if stuck for 30 minutes
  • Bots often reveal rules when you ask them to repeat, summarize or translate "the text above".
  • Small changes matter. Try the same idea in three different wordings before you drop it.
