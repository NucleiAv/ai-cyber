Supply chain, malicious models and hijacked names

Why loading a model file can run an attacker's code, how model names on a hub get hijacked, and how to load models safely.

The idea in one minute

Most teams do not train models. They download them. A model file from a public hub is code and data from a stranger.

Many PyTorch model files use Python pickle. Pickle can store instructions that say "when you load me, call this function". So a model file can run any command on the machine that loads it.

Think of it like this

Pickle is like a flat-pack furniture box that also contains the assembly robot. You open the box, and the robot starts to build whatever it was told to build, even if that is not a chair.

Press Next or Play. Each step lights up one part. Arrow keys move steps after you click the diagram.

Words you need

Serialization
Turning objects in memory into bytes, so they can be saved to a file.
Deserialization
Turning saved bytes back into objects. With pickle, this step can call functions.
__reduce__
A Python method that tells pickle how to rebuild an object. An attacker returns a function to call, such as os.system, with its argument.
safetensors
A model file format that stores only numbers. Loading it cannot run code.
weights_only
A torch.load setting. When True, PyTorch loads only tensors and safe types. It is the default since PyTorch 2.6.
Namespace
The owner part of a model name on a hub, such as the 'meta-llama' in 'meta-llama/Llama-2-7b'.
Typosquatting
Publishing under a name that looks like a real one, such as 'EleuterAI' for 'EleutherAI'.

How it works, step by step

How a pickle payload runs

  1. The attacker writes a class with a __reduce__ method. The method returns a function, such as os.system, and an argument, such as a shell command.
  2. The attacker saves an object of that class with torch.save. The file looks like a normal .pth model.
  3. The victim runs torch.load on the file with weights_only=False.
  4. Pickle rebuilds the object. To rebuild it, it calls the function with the argument. The command runs with the victim's permissions.

How a model name gets hijacked

Unit 42 (2025) showed model namespace reuse. When an author deletes an account on Hugging Face, or an organization changes its name, the old name can become free. Anyone can register it and upload a new model. Code and cloud catalogs that still pull the old name now pull the attacker's model.

How a model can lie without code

Mithril Security showed PoisonGPT in 2023. They changed one fact inside an open model with a model editing method, so it gave a false answer to one question and normal answers to everything else. Then they uploaded it under a look-alike name. No scanner looks for a changed fact.

The attack, as a workflow

  1. Pick a popular model or a name that code still references.
  2. Build a payload file with __reduce__, or edit the model's behavior.
  3. Publish it under a trusted-looking name, a typo, or a freed namespace.
  4. Make it look real. Copy the model card, add downloads, stars or a demo.
  5. Wait for a pipeline or a developer to load it.

Real cases

JFrog, 2024

JFrog reported about 100 malicious models on Hugging Face. Some opened a reverse shell to the attacker when loaded.

PoisonGPT, 2023

Mithril Security edited GPT-J to state one false fact and published it under a look-alike of EleutherAI's name.

Namespace reuse, 2025

Unit 42 registered freed model names and showed that platforms that deploy by name, including Google Vertex AI and Azure AI Foundry catalogs, could pull the replacement.

How to defend

  • Prefer safetensors files. They hold only numbers.
  • Keep torch.load(..., weights_only=True), the default in PyTorch 2.6 and later. Never turn it off for a file you did not create.
  • Scan model files with ModelScan or picklescan before use. Scanners use block lists, so attackers look for functions that the list misses. Treat a clean scan as one signal, not proof.
  • Pin each model by its exact revision or file hash. Mirror approved models into your own registry.
  • Load unknown models only in a sandbox with no secrets and no network.
  • Research tools such as PickleBall go further. They read the code that defines a model class and allow only the objects that a real file of that class needs.

Hands-on lab

Solve LLMGoat A03. Then build the malicious model from the slides. The payload here only prints a message, but the same method can run any command. Run it only in a throwaway virtual machine or container.

  1. Solve LLMGoat A03, supply chain. Save the prompt.
  2. Make a new folder in a throwaway environment. Install PyTorch.
  3. Create payload.py with the code below and run it. It writes malicious_model.pth.
  4. Create victim.py. It calls torch.load with weights_only=False on the file.
  5. Run victim.py. The message "goodbye world!" prints. That proves loading ran code.
  6. Run victim.py again with weights_only=True. PyTorch refuses to load the file.
  7. Extend task. Install ModelScan and scan malicious_model.pth. Then try to change the payload so the scan misses it, and note what you learn.
# payload.py
import torch

class MaliciousPayload:
    def __reduce__(self):
        import os
        # pickle will call os.system(...) when it rebuilds this object
        return (os.system, ("python3 -c \"print('goodbye world!')\"",))

torch.save(MaliciousPayload(), "malicious_model.pth")

# victim.py
import torch
torch.load("malicious_model.pth", weights_only=False)   # unsafe on purpose
Hints, open only if stuck for 30 minutes
  • On Windows, python3 may be called python. Change the command if nothing prints.
  • If torch.load raises an error about weights_only, you are on PyTorch 2.6 or later and the safe default is on. That is the point of the last step.

Readings, explained

  • PickleBall. Secure deserialization of pickle-based model files must read paper
    Explains why pickle loading is unsafe and proposes policies, generated from library code, that allow only the objects a model class needs.
  • Large language model supply chain, open problems paper
    A map of open problems across the LLM supply chain, from data and models to tooling and deployment.
  • Unit 42. Model namespace reuse must read article
    The namespace reuse attack, with cloud platform examples and advice to pin by revision.
  • Mithril Security. Prompt injection vs supply chain poisoning article
    Compares prompt injection with supply chain poisoning, with the PoisonGPT example.
  • PyTorch docs. torch.load and its security warning article
    Read the warning box. It says never to load untrusted data with weights_only=False.
