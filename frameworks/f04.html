STRIDE, threat modeling an LLM app

A simple way to find what can go wrong in a design before attackers do. Draw the system, then walk six kinds of threat across every part.

The idea in one minute

Threat modeling means thinking about attacks while you design, when fixes are cheap. STRIDE is a checklist of six threat types. Loren Kohnfelder and Praerit Garg created it at Microsoft in 1999.

Each letter is a threat, and each threat breaks one security property.

Think of it like this

Before you move into a house, you walk every room and ask six questions. Can someone pretend to be me? Change my things? Deny they did something? See my secrets? Lock me out? Get a master key? STRIDE is those six questions for software.

Words you need

Spoofing
Pretending to be someone or something else. Breaks authentication.
Tampering
Changing data or code without permission. Breaks integrity.
Repudiation
Denying an action with no proof either way. Breaks non-repudiation.
Information disclosure
Showing data to someone not allowed to see it. Breaks confidentiality.
Denial of service
Making the system unavailable. Breaks availability.
Elevation of privilege
Getting more power than allowed. Breaks authorization.
Data flow diagram
A simple drawing of processes, data stores, external entities, data flows and trust boundaries.
Trust boundary
A line where data moves between parts with different trust, such as from the internet into your server.

How it works, step by step

The four questions

Adam Shostack's four-question frame is the shortest guide to any threat model.

  1. What are we working on?
  2. What can go wrong?
  3. What are we going to do about it?
  4. Did we do a good job?

STRIDE answers question 2.

STRIDE on an LLM support bot

  • Spoofing. A user types a fake system block and the model treats it as the developer. (Module 9, Yarrow Mutual.)
  • Tampering. An attacker edits a document in the RAG store. (Lesson 7, poisoning.)
  • Repudiation. The agent sends a refund, and no log shows which prompt caused it.
  • Information disclosure. The bot repeats its system prompt or another user's data. (Lessons 4 and 11.)
  • Denial of service. A sponge prompt burns the token budget. (Lesson 14.)
  • Elevation of privilege. An injected instruction makes the agent use tools the user may not use. (Lesson 9.)

How to use it, step by step

  1. Draw the data flow diagram. Include every external entity, process, data store and flow.
  2. Draw the trust boundaries.
  3. For each element and each flow, ask the six STRIDE questions.
  4. Write each threat as one sentence, such as "An outsider can tamper with the vector store through uploads".
  5. Choose a response for each. Mitigate, remove the feature, transfer the risk, or accept it with a named owner.
  6. Check your list against the OWASP LLM Top 10 to catch misses.
  7. Repeat when the design changes.

Real examples

Yarrow Claims Assistant

STRIDE finds information disclosure on the outbound email flow and tampering on inbound email. Removing the outbound channel answers both. Module 9 reaches the same fix through the lethal trifecta.

Fernhill Contractor API

Elevation of privilege on the unauthenticated model reload endpoint, found in Module 11. A data flow diagram shows that flow crossing the trust boundary with no check.

Strengths and limits

Strengths

  • Easy to learn and quick to run in a design meeting.
  • Works on any system, including LLM apps and agents.
  • Free tools help, such as the Microsoft Threat Modeling Tool and OWASP Threat Dragon.

Limits

  • It finds threat types, not their likelihood. Rank them with risk or real data.
  • It depends on a correct diagram. Missing a flow means missing its threats.
  • LLM-specific risks, such as prompt injection, can hide inside Spoofing, Tampering and Elevation, so add the OWASP list as a second pass.

Try it

Threat model the email agent from lesson 9.

  1. Draw its data flow diagram. User, agent, mail API, inbox, outside senders.
  2. Mark the trust boundary where outside email enters.

  4. Pick a response for each and name an owner.
