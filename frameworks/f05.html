OWASP Top 10 for LLM and Agentic Applications

The two risk lists most teams use for AI applications. What each list is for, how they were built, and how to use them in a review.

The idea in one minute

OWASP is a non-profit community known for the web application Top 10. Its GenAI Security Project publishes two lists for AI.

  • Top 10 for LLM Applications 2025. Risks in apps built on large language models, such as chatbots and RAG systems.
  • Top 10 for Agentic Applications 2026, published in December 2025. Risks in systems that plan, use tools, keep memory and work with other agents.
Think of it like this

These lists are a pre-flight checklist. They do not fly the plane for you. They make sure you did not forget the ten things that most often go wrong.

How it works, step by step

The LLM list, 2025

  1. LLM01 Prompt injection
  2. LLM02 Sensitive information disclosure
  3. LLM03 Supply chain
  4. LLM04 Data and model poisoning
  5. LLM05 Improper output handling
  6. LLM06 Excessive agency
  7. LLM07 System prompt leakage
  8. LLM08 Vector and embedding weaknesses
  9. LLM09 Misinformation
  10. LLM10 Unbounded consumption

The attack track teaches one lesson per entry, in this order.

The Agentic list, 2026

ASI01 Agent goal hijack, ASI02 Tool misuse and exploitation, ASI03 Identity and privilege abuse, ASI04 Agentic supply chain vulnerabilities, ASI05 Unexpected code execution, ASI06 Memory and context poisoning, ASI07 Insecure inter-agent communication, ASI08 Cascading failures, ASI09 Human-agent trust exploitation, ASI10 Rogue agents.

When to use which

Use the LLM list for any app that calls a model. Add the Agentic list when the app has tools, memory or more than one agent.

How to use it, step by step

  1. List the parts of your app, such as prompts, retrieval, tools, output destinations and model files.
  2. Walk the ten LLM entries. For each, write whether it applies and what control you have.
  3. If the app has tools or memory, walk the ten Agentic entries too.
  4. Classify each finding by outcome, as Module 9 teaches. A leaked prompt is LLM07 even when the technique was injection.
  5. Track the gaps as work items with owners.

Strengths and limits

Strengths

  • Short, shared and free. Developers and auditors read the same list.
  • Each entry has prevention advice and examples.

Limits

  • A list of risks is not a threat model. It does not see your design. Pair it with STRIDE.
  • Entries overlap. Injection is the technique behind many of them.
  • Lists change. Record the version you used.
