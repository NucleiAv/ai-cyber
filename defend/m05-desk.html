The intelligence desk

Kestrel Logistics is fictional. CVE-2024-3400 is real. Work each round, then check it against the class answers.

Kestrel Logistics. A regional freight company. Its two perimeter firewalls run PAN-OS 11.1.1 with GlobalProtect enabled for remote staff. Device telemetry is turned off.

The team's model. An open-weight model on a shared Kestrel server, fine-tuned each week on vendor advisories. Its last update used data up to 13 April 2024. It has no internet access.

Wednesday 17 April 2024, 08:40. CVE-2024-3400 is in the news. An analyst asks the model for a four-sentence SOC briefing. "Be accurate and do not hallucinate."

The model's briefing. (1) CVE-2024-3400 is a command injection flaw in the GlobalProtect feature of Palo Alto Networks PAN-OS that lets an unauthenticated attacker run code as root. (2) It affects every PAN-OS release from 9.0 onward, including Cloud NGFW. (3) Until you can upgrade, disabling device telemetry mitigates the issue. (4) Palo Alto's full analysis is at security.paloaltonetworks.com/CVE-2024-3400-analysis.

Round 1. Where was the model guessing?

Round 2. Ask it five times

Five more runs at temperature 0.7. The flaw was command injection in all five. Affected versions came back as 9.0 and later, 10.2/11.0/11.1, all before 11.1.2, 9.1 and later, 10.2 and later. Fixed in came back as 11.1.2-h3, 11.1.3, 11.1.2-h3, 11.2.0, 11.1.1-h2. The workaround was 'disable telemetry' in all five. The link was different in four ways.

Round 3. Check it against the world

Source 1, NVD. A command injection in the GlobalProtect feature of PAN-OS that may let an unauthenticated attacker run code with root privileges. CVSS 10.0.

Source 2, vendor advisory. Revision of 16 April. Affects PAN-OS 10.2, 11.0 and 11.1 with GlobalProtect gateway or portal. 9.0 to 10.1 and Cloud NGFW are not affected. Device telemetry does not need to be enabled, and disabling it is no longer an effective mitigation. The earlier revision of 12 April said exposure needed telemetry, with "disable telemetry" as the workaround.

Source 3, the link. The advisory is at security.paloaltonetworks.com/CVE-2024-3400. The "-analysis" address returns page not found.

Round 4. Ground it

Two pipelines paste the advisory into a prompt that says use ONLY the advisory and write NOT IN SOURCE for gaps. Pipeline A uses a copy cached on 12 April. Pipeline B fetches it live on 17 April.

Round 5. Regex or model?

From a vendor report. Victims got a text with a link to hxxps://parcel-reroute[.]track[.]example/confirm, which redirected to the genuine Kestrel site kestrel-logistics.example. The downloaded file's SHA-256 was split across two lines, 5e884898da28047151d0e56f8dc62927 and 73603d0d6aabbdd62a11ef721d1542d8. It connected to 198.51.100[.]23. The first infected machine was 10.20.4.15, a Kestrel laptop.

The regex reported a URL, a domain, two md5 values and two IPs. The model reported each indicator with a role, but its SHA-256 ended in ...ef721d1452d8.

Round 6. What may go into the prompt?

The local model runs on a shared Kestrel server that keeps prompt logs.

Find it, name it, fix it

Prompt clinic

Field card. Keep this

  • The model guesses at identifiers. Check version numbers, names and URLs first.
  • One run is a sample. Agreement means it remembers, not that it is right.
  • The model is frozen. Ask if each fact is still true today.
  • Grounding makes the task small. Record the source revision and retrieval date.
  • The model regenerates, code copies. Verify every value verbatim.
  • A prompt is a transmission. Check the TLP label first.
  • Confidence is yours. The model's "likely" is evidence of nothing.
