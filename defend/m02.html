How LLMs work

From text to tokens to vectors to a next-token guess. Where model behavior comes from, how to map risks to the model lifecycle, and why models make things up.

The idea in one minute

To defend an LLM system you need a mental model of what happens inside it. The model turns text into tokens, tokens into vectors, mixes them with attention, and outputs a probability for every possible next token. Then it picks one and repeats.

Everything the model "knows" is in its weights from training. Everything it "sees" right now is in its context window. Most risks live in one of those two places.

Think of it like this

Think of autocomplete on your phone, trained on a huge library and made very smart. It still only guesses the next word. It does not look anything up unless you hand it a page to read.

Learn it from zero

Step 1. Text becomes tokens

A tokenizer cuts text into tokens. Common words are one token. Rare strings, such as IP addresses, hashes and hex dumps, break into many tokens. This is the token tax on security data. Logs cost more and fill the context window faster than normal prose.

Step 2. Tokens become vectors

Each token maps to an embedding, a list of numbers. Training places related tokens near each other. Similarity is usually measured with cosine similarity, because the direction of a vector carries the meaning.

Step 3. Attention mixes context

Transformer layers let every token look at the tokens before it and decide which ones matter. After many layers, the last position holds a summary used to predict what comes next.

Step 4. Probabilities and sampling

The model gives a probability to every token in its vocabulary. Temperature controls the pick. At 0 it takes the most likely token every time. Higher values add randomness. That is why the same prompt can give different answers.

Step 5. Where behavior comes from

Behavior is a stack, not one source.

  1. Pretraining gives broad knowledge, stored in the weights. This is parametric memory, frozen at a cutoff date.
  2. Post-training shapes behavior. Supervised fine-tuning teaches format. RLHF trains a reward model from human preferences and then tunes the model toward it. DPO learns directly from preference pairs, without a separate reward model.
  3. Inference time adds the system prompt, retrieved documents, tool results and decoding settings.

Step 6. Why models fabricate

Two different failures look alike. Fabrication is confident false content, such as an invented CVE or URL. Variability is a different answer on each run. Version numbers and identifiers are where models guess most, because many numbers are plausible and none stands out.

Key point

Deploying a model locally keeps data on your servers. It does not make the system secure. Data residency and security are different questions.

Words you need

Token
A small piece of text that the model reads and writes.
Context window
The maximum number of tokens the model can read at once.
Embedding
A vector of numbers that stands for a token or a text.
Attention
The mechanism that lets each token weigh other tokens.
Temperature
A setting that controls how random the next-token pick is.
RLHF
Reinforcement learning from human feedback. A reward model learned from human rankings guides tuning.
DPO
Direct preference optimization. Learns from preferred and rejected answers without a separate reward model.
Quantization
Storing weights with fewer bits. Smaller and faster, with some loss of quality.
Model card
A document that describes a model's training, intended use and limits.
