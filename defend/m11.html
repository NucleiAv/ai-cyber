Defending AI systems

Stack layers that fail for different reasons, treat model output as untrusted, close the API door, detect abuse in logs, respond to AI incidents, and check AI's own defensive work.

The idea in one minute

No single control stops attacks on an AI system. So defenders stack layers. The trick is that layers multiply only when they fail for different reasons. Two classifiers trained on the same jailbreak data miss the same new prompts.

This module builds a full defense for one public service. Guardrails, output encoding, schema checks, API authentication, token budgets, detection rules and incident response. Then it turns AI around and asks how far to trust AI doing defensive work.

Think of it like this

Two locks from the same factory with the same flaw open with the same trick. A lock and a guard dog and a camera fail for different reasons, so a thief must beat all three.

Learn it from zero

Step 1. Input and output guardrails

Guardrails check text before and after the model. Keyword filters are cheap. Classifiers catch more. Both are tuned on known attacks, so their scores on new attacks are much lower. Ask what a guardrail's accuracy was measured on. Prefer an honest low number on new attacks to a high number on known ones.

Step 2. Treat output as untrusted

The same model output can be harmless in one place and dangerous in another. In a web page it needs output encoding. In a database query it needs a schema check or parameters. These deterministic controls work whatever the text says. A second model reviewing output is probabilistic and reads the same attacker-controlled text.

Step 3. Three deployment patterns

A chatbot has the smallest attack surface. RAG adds four retrieval surfaces, such as poisoned documents, cross-tenant leakage, adversarial embeddings and the retrieval pipeline itself. An API-exposed model adds lifecycle endpoints, such as model reload and config, which must never be public.

Step 4. Detect abuse in logs

Compare two signals. Did the input guardrail flag it? Is the output normal? Flagged plus normal means the controls worked. Not flagged plus odd output means something got past the input checks. Investigate that first.

Step 5. Respond to an AI incident

A replay is not a reproduction, because the model is random and its context may have changed. Log the full request, the full output, the retrieved documents and the guardrail verdicts at the time. Containment means removing the data source the model copies from, not just disconnecting a server.

Step 6. AI for defense

AI helps with infrastructure-as-code review, YARA rule drafts, IAM analysis and malware classification. Each has a known failure. Keep the speed and aim one cheap check at that failure, such as compiling a YARA rule in the exact engine you run.

Words you need

Guardrail
A check before or after the model that blocks unsafe input or output.
Defense in depth
Several independent layers, so one failure does not mean a breach.
Output encoding
Showing special characters as text, so markup cannot run.
Schema check
Accepting only values that match an allowed format or list.
Inference endpoint
An API that answers requests.
Lifecycle endpoint
An API that manages the model, such as reload, config or retrain.
Compound detection
Combining weak signals so their mix shows an attack.
Containment
Stopping an incident from spreading or continuing.
