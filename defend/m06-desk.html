The code review desk

Larkspur Pay runs online payments for small merchants. It has 50 developers and one security engineer. You are that engineer today.

Round 1. One checker among severalRound 2. Testing the testRound 3. From flagged to confirmedRound 4. Where Larkspur trusts othersFind it, name it, fix itPrompt clinic

Monday 08:55. The AI reviewer comments on a pull request. "No security issues found in this change." Today's question is what that comment actually tells you.

The AI reviewer receives two things, the changed code and the instruction "Review this change for security vulnerabilities". It does not get Larkspur's business rules or policies.

Round 1. One checker among several

Round 2. Testing the test

A vendor's slide says 'AI finds vulnerabilities with a score of 68 percent' (F1 on BigVul). An audit of BigVul found wrong labels (3 in 4 'vulnerable' pieces were not), duplicates (about 1 in 8 test pieces were copies of training pieces) and the same time period for test and training.

Round 3. From flagged to confirmed

When a merchant clicks Download, the browser opens /invoices/1042. The server looks up invoice 1042, finds where its file is stored and sends it. Facts. (a) The link holds only an invoice number. (b) Larkspur sets where files are stored, never the visitor. (c) You must log in as a merchant, and any business can sign up. (d) Invoice numbers go up in order.

Prompt clinic

Field card. Keep this

  • The AI reviewer sees only what it is given and never runs the code.
  • A benchmark score is only as good as its labels, splits and dates.
  • Prefer specific CWE labels. They point to the fix.
  • A warning is a guess. A test gives the verdict.
  • Every package, and every AI-suggested package, is a trust decision.
