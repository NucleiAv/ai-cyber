AI for threat intelligence

What a language model does when you ask it about a vulnerability. Guessing, stale truth, grounding, IoC extraction, sharing rules and a verification routine you can use every day.

The idea in one minute

Threat intelligence turns raw data into decisions, such as "patch these two firewalls today". A model can draft summaries fast. But a model with no source answers from its weights, which are frozen at a date. It guesses at version numbers, repeats advice that was later withdrawn, and invents links, all in the same confident tone.

This module teaches a routine. Decompose a claim, route it to the source that owns it, check that it is still true today, and grade your confidence.

Think of it like this

A friend who read the news last spring can tell you a lot. But if you ask about today, they will answer from memory and sound just as sure. You still check today's paper.

Learn it from zero

Step 1. Data, information, intelligence

Data is raw, such as a log line. Information is data with meaning, such as "this IP scanned us". Intelligence is information shaped for a decision and a customer, such as "patch the VPN gateway by tonight". The intelligence cycle runs direction, collection, processing, analysis, dissemination and feedback.

Step 2. The ground truth sources

  • CVE record (cve.org). Says a vulnerability exists and gives its ID.
  • NVD. Adds a CVSS severity score and vector. Severity is not risk.
  • EPSS. Predicts the chance of exploitation soon. It is recalculated daily.
  • CISA KEV catalog. Lists vulnerabilities known to be exploited. Absence from KEV does not mean safety.
  • Vendor advisory, latest revision. Affected versions, fixes and workarounds.
  • Your own inventory. Whether you are exposed. No public model has seen it.

Step 3. How a model fails at intelligence

  • It guesses identifiers. Version numbers and URL paths are low-probability tokens.
  • It varies. Five runs give five different "fixed in" versions.
  • It agrees on stale facts. A withdrawn workaround can come back the same in every run.
  • It fabricates references. A plausible advisory URL can return a 404.

Step 4. Grounding

Paste the source into the prompt and say "use ONLY this text, and write NOT IN SOURCE for gaps". This turns recall into rewriting. But grounding is only as current as the document you fetched, so print the source revision and the retrieval date on every briefing.

Step 5. Let code copy, let the model judge

For indicators of compromise, a regex copies strings exactly but cannot tell an attacker's domain from the victim's. A model can judge roles but may change a character when it rewrites a hash. Use code to find and copy, the model to judge roles, and code again to check every value appears verbatim in the source.

Step 6. Sharing rules and confidence words

TLP labels say who may see a report. RED is named recipients only. AMBER+STRICT is your organization only. AMBER adds clients on a need-to-know basis. GREEN is your community. CLEAR is anyone. A prompt to an outside service is a transmission, so check the label first. When you sign off, use estimative language with agreed ranges, such as "likely" for 55 to 80 percent, and grade only what you verified.

Words you need

CVE
Common Vulnerabilities and Exposures. A unique ID for a public vulnerability.
CVSS
A 0 to 10 severity score with a vector that explains it.
EPSS
Exploit Prediction Scoring System. The chance a CVE is exploited in the next 30 days.
KEV
CISA's Known Exploited Vulnerabilities catalog.
IoC
Indicator of compromise, such as a malicious IP, domain or file hash.
STIX and TAXII
A standard format for threat intelligence (STIX) and a protocol to share it (TAXII).
TLP
Traffic Light Protocol. Labels that say who may receive a piece of intelligence.
Stale truth
A fact that was true when the model's data was collected and is no longer true.
Grounding
Giving the model the source text and telling it to answer only from it.
