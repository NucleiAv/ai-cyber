AI foundations

What AI and machine learning really are, how a model learns, how to measure a detector, and how AI changes the security field.

The idea in one minute

Security tools used to be lists of rules written by people. A rule catches exactly what it describes and nothing new. Machine learning lets a computer learn its own rules from examples, so it can catch things nobody wrote a rule for.

This module builds the words you need for the rest of the course. It also teaches the most useful skill in security AI. Measure a detector with the right numbers, not with one big accuracy score.

Think of it like this

A rule is a "wanted" poster with one face. Machine learning is a guard who has seen ten thousand thieves and learned what thieves tend to look like. The guard can spot a new thief, but can also be fooled, and can make mistakes.

Learn it from zero

Step 1. The family tree

AI is the big circle. Inside it is machine learning, programs that learn from data. Inside that is deep learning, machine learning with many-layer neural networks. Inside that are large language models. Every LLM is deep learning, but most AI in security is not an LLM.

Step 2. Three ways to learn

  • Supervised learning. Examples come with answers, called labels, such as "malicious" or "benign". The model learns to predict the label. Most detectors work this way.
  • Unsupervised learning. No labels. The model finds groups and outliers. Good for "this traffic is unusual".
  • Reinforcement learning. The model acts, gets a reward or a penalty, and learns which actions pay off.

Step 3. Train, then use

Training adjusts the model's numbers, called weights or parameters, until its guesses match the labels. Inference is using the trained model on new data. A model must be tested on data it did not train on, or the score means nothing.

Step 4. Measure it honestly

Every prediction lands in one cell of the confusion matrix.

  • True positive (TP). It said malicious, and it was.
  • False positive (FP). It said malicious, but it was benign. This wastes analyst time.
  • False negative (FN). It said benign, but it was malicious. This is a missed attack.
  • True negative (TN). It said benign, and it was.

From these, precision = TP ÷ (TP + FP) answers "of what it flagged, how much was real?" Recall = TP ÷ (TP + FN) answers "of the real attacks, how many did it catch?" Security data is mostly benign, so plain accuracy flatters bad detectors.

Fact check

On a dataset that is 80 percent benign, a detector that says "benign" every time scores 80 percent accuracy and catches nothing. Module 4 uses this exact example with CIC-IDS2017.

Step 5. Language models and hallucination

An LLM predicts the next token. It has no built-in fact check. So hallucination, fluent but false output, is part of how it works, not a bug that one patch can remove.

Step 6. Why this matters now

AI lowers the skill and cost an attacker needs, speeds up attacks, and helps defenders too. This is dual use. Before you trust any "AI-powered" claim, ask what type of AI it is, what data it learned from, and how it was measured.

Words you need

Model
The learned rules, stored as numbers called weights.
Feature
A measurable input to a model, such as bytes sent or packet count.
Label
The right answer attached to a training example.
Overfitting
The model memorizes training data and fails on new data.
Precision
Of the alerts it raised, the share that were real.
Recall
Of the real attacks, the share it caught.
F1
One number that balances precision and recall. It is high only when both are high.
Dual use
The same capability helps both defenders and attackers.
