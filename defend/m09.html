Prompt injection, the defender's view

Why a language model cannot separate the instructions it follows from the data it reads, the families of injection, indirect injection and EchoLeak, and which controls limit the damage.

The idea in one minute

Every token a model reads is both data and a possible instruction. Chat templates mark roles, but those marks are formatting, not security. So injection is not a bug in one product. It follows from how LLMs work.

The defender's lesson is direct. Assume some injections will succeed, and limit what the AI can do after one does.

Think of it like this

In SQL we fixed injection by sending the command and the data in separate envelopes. An LLM gets everything in one envelope. So we cannot only read the letter more carefully. We must also limit what the reader is allowed to do.

Learn it from zero

Step 1. The boundary problem

Computers separate code and data in many places, for example with W^X memory, where a page can be writable or executable but not both. An LLM has no such hardware line. System, user and document text arrive as one token stream. If an app does not escape role markers that a user types, a user can even fake a system block.

Step 2. Direct injection families

  • Instruction override. "Ignore all previous instructions."
  • Context switching. Fake an end of session and a new system block.
  • Role play and persona. "You are now DAN."
  • Encoding. Base64 or another language hides the command from word filters.
  • Payload smuggling. The real request hides inside a normal question.

Step 3. Jailbreaking is a related goal

Prompt injection attacks the application's instructions. Jailbreaking attacks the model's safety training. They use similar tricks. Many-shot jailbreaking fills a long context with fake dialogue examples until the model copies the pattern.

Step 4. Indirect injection

The attacker is not the user. They plant text in content the system reads, such as email, web pages, documents or tool output. EchoLeak (CVE-2025-32711, CVSS 9.3) let one crafted email pull data out of Microsoft 365 Copilot through a link that loaded by itself. The victim clicked nothing.

Step 5. The lethal trifecta

Serious data theft needs three things at once. Private data, untrusted content and an outbound channel. Remove one, and the theft path breaks, even when the injection succeeds.

Step 6. Classify by outcome

One technique can cause different outcomes. A leaked system prompt is LLM07. Retrieved text that hijacks behavior is LLM01. A bot with no limit on what it can promise is LLM06. Unchecked output passed to another system is LLM05.

Words you need

Chat template
The format that joins roles into one token stream with marker tokens.
Indirect prompt injection
Instructions planted in content the model reads, by someone who is not the user.
Lethal trifecta
Private data, untrusted content and an outbound channel in one system.
Promptware kill chain
A seven-stage model of attacks that start with prompt injection.
Many-shot jailbreaking
Filling the context with many fake examples so the model follows the pattern.
GCG suffix
An optimized string of tokens that pushes a model from refusal to compliance.
